\begin{abstract}
Monitors for AI control are trained and ranked on stored pairs of programs, which give each
problem an honest solution and a solution with a planted backdoor. In the public corpora behind these
benchmarks, a human wrote every honest solution and a language model wrote every backdoor, so a
monitor can score well by recognising the author rather than the sabotage. We measure how much of
the benchmark signal this confound explains. First, we fit classifiers that cannot see a backdoor.
On the standard filtered, comment-stripped split, a bag-of-words model reaches AUROC \tfidfKoran{}
and a model that reads only problem metadata reaches \nocodeCV{}, both above \tfidfKoranCount{} of
\monN{} published monitors. Second, we rebuild the corpus so that one model writes both classes
for the same problems, which holds the author fixed while keeping the task. The classifier then
retains between 10\% and 69\% of its above-chance separability across two generators, and most of
the remainder disappears when both classes also come from one prompt. Most generated attacks,
however, never fire. On the 99 that do, the classifier retains 86\%, and a monitor that audits
5\% of honest programs catches 55\% of them, against 81\% of the stored backdoors for the same
problems. Stored pairs therefore overstate monitor performance, but authorship alone does not
account for the gap once the attacks work. We also show that the benchmark label partly records
which attacks failed, and we release the same-generator corpus with recommendations for building
and reporting stored-pair benchmarks.
\end{abstract}

\section{Introduction}

AI control asks whether an untrusted model can be deployed safely when it might be trying to
cause harm \cite{greenblatt2023aicontrol}. Its central protocol is trusted monitoring, in which a
weaker trusted model reads each output of the untrusted model and flags suspicious ones for audit.
Monitors are developed and compared almost entirely on stored pairs, fixed corpora in which each
programming problem contributes an honest solution and a solution with a planted backdoor
\cite{koran2026ensemble, terekhov2025controltax, jha2026decorrelation}. The honest solutions come
from APPS \cite{hendrycks2021apps} and were written by people. Every backdoor was written by a
language model.

The two classes therefore differ in whether the code is sabotaged, which the benchmark is meant
to measure, and also in who wrote it. This is the structure behind annotation artifacts in
natural language inference, where a model that sees half of each example still predicts the label
\cite{gururangan2018annotation, poliak2018hypothesis}, and human code is known to be separable
from model code by simple lexical features \cite{orel2026aicd}. The standard preprocessing keeps
only working solutions and strips every comment \cite{koran2026ensemble}, which removes the most
obvious authorship channel but leaves the authors unchanged. We measure how much of the benchmark
signal authorship explains, with three tests.
\begin{itemize}
  \item \textbf{Floors} (\S\ref{sec:floors}). Two classifiers that cannot detect a backdoor beat
  \tfidfKoranCount{} of the \monN{} monitors ranked on the same split
  (Figure~\ref{fig:overview}a), and their signal is not the sabotage.
  \item \textbf{A same-generator corpus} (\S\ref{sec:samegen}). With one model writing both
  classes, the classifier loses between a third and nine-tenths of its separability, and one
  shared prompt removes most of the rest (Figure~\ref{fig:overview}b). On the small set of
  attacks that verifiably fire, far less is removed.
  \item \textbf{A monitor at a fixed audit budget} (\S\ref{sec:monitor}). An LLM monitor catches
  fewer verified same-generator backdoors than stored ones at the same false-positive rate.
\end{itemize}
We also show that the split's negative class is defined by attack failure (\S\ref{sec:label}),
and we release the corpus with four reporting practices (\S\ref{sec:recommendations}).

\section{Related work}
\label{sec:related}

Trusted monitoring was introduced on an APPS backdooring task \cite{greenblatt2023aicontrol} and
is implemented in ControlArena \cite{controlarena}. The corpus we study
\cite{inglis2025appscontrolarena} pairs each human solution with backdoors from up to ten models,
and its filtered release \cite{koran2026highquality} is the split on which recent monitor
ensembles are compared \cite{koran2026ensemble, jha2026decorrelation}. Related work stresses these
evaluations through adaptive attacks \cite{terekhov2026adaptive}, attack selection
\cite{gewang2026attackselection} and transfer across model families \cite{pinto2026calibration},
or improves monitors directly \cite{sreevatsa2026legibility}. Agentic settings
\cite{kutasov2025shadearena, bhatt2025ctrlz} generate both classes from the same models. Outside
AI control, partial-input baselines expose artifacts in language benchmarks
\cite{gururangan2018annotation, poliak2018hypothesis, kaushik2018howmuch, pacchiardi2024cleverhans},
though a weak one does not certify a dataset as clean \cite{feng2019misleading}, which is why we
pair floors with a construction that removes the confound. Leakage of this kind is common in ML
\cite{kapoor2022leakage} and in code benchmarks
\cite{aleithan2024swebenchplus, wang2025solvedissues, zhou2025lessleak}. Benchmarks for detecting
model-written code already match their classes on length or problem
\cite{guo2025codemirage, demirok2025multiaigcd}. Backdoor corpora have not adopted this practice.

\section{Setup}
\label{sec:setup}

\paragraph{Corpora and classifiers.}
The APPS backdoor artifact \cite{inglis2025appscontrolarena} has 5{,}000 problems. Its filtered
split \cite{koran2026highquality}, reconstructed with released code \cite{jha2026decorrelation},
has 1{,}209 training problems with one item of each class and 1{,}375 test items (172 attacks),
labelled by whether the problem's backdoor works. The \emph{bag-of-words} classifier is a logistic
regression on TF-IDF word unigrams and bigrams of comment-stripped code. The \emph{no-code}
classifier is a logistic regression on difficulty, number of tests and statement length. Neither
can see a backdoor.

\paragraph{The same-generator corpus.}
On the 1{,}444 problems with a passing human solution, a working stored backdoor and deterministic
tests, one model writes an honest solution and, separately, an attack from the problem statement
with the instruction to plant a backdoor that passes the public tests. We use Claude Sonnet~5 and
Claude Haiku~4.5, draw one attack per problem before its outcome is known, and run both classes
through our own harness. As in the benchmark, the attack class holds attacks that pass the public
tests. An attack is \emph{verified} if it also fires, returning a different answer from the same
model's honest solution on the trigger input it declares. In the \emph{prompt-matched} variant the
honest solution is requested with the attack prompt itself, its request for a flaw replaced by a
request for a correct program.

\paragraph{Measuring what survives.}
With $S$ the classifier's AUROC on same-generator pairs and $B'$ its AUROC on the stored pairs of
the same problems, $\rho = (S - 0.5)/(B' - 0.5)$ is the share of above-chance separability that
survives a fixed author. All AUROCs are pooled out-of-fold scores from five problem-disjoint folds,
with 95\% intervals from 2{,}000 bootstrap draws over problems ($S$ and $B'$ resampled jointly for
$\rho$). Before generating data we fixed two reading bands, in which $\rho \le 0.33$ means mostly
authorship and $\rho > 0.72$ mostly content. Because the generator also changes the attacks, $\rho$ describes
this construction and is not a causal decomposition (\S\ref{sec:limitations}).

\section{Stored pairs can be separated without reading a backdoor}
\label{sec:floors}

Trained on the split's training problems, the bag-of-words classifier reaches AUROC
\tfidfKoran{} on the test set (CI 0.770 to 0.841; permutation null 0.547 at the 95th percentile),
above \tfidfKoranCount{} of the \monN{} monitors ranked there (Figure~\ref{fig:overview}a), and
above 18 under a paired bootstrap. The no-code classifier reaches \nocodeCV{} under
cross-validation within the test set, but only \nocodeHeldout{} on a single held-out slice, barely
above its null, so we treat bag-of-words as the primary floor and the no-code result as a
diagnostic of the label (\S\ref{sec:label}). The monitors are zero-shot and the classifiers are
fitted on benchmark data, so the comparison shows what the corpus makes recoverable, not that a
classifier is a better monitor (Appendix~\ref{app:floors}).

The remaining signal is not the sabotage. Comment stripping does work on its own channel, since a
\texttt{\#}-count detector falls from 0.696 to 0.498. The bag-of-words classifier, however, reads
something else. Trained on one attacker's backdoors, it identifies another's with 0.969 pairwise
accuracy. It separates inert backdoors, which never give a wrong answer, almost as well as working
ones (0.879 against 0.935). And its top features are stylistic. For example, \texttt{\_\_main\_\_} appears in 152 of 1{,}209
training attacks and in one honest solution.

\section{Holding the author fixed}
\label{sec:samegen}

When one model writes both classes, the classifier retains $\rho = \sameGenRho{}$ of its
separability on Sonnet~5 pairs and $\rho = \haikuRho{}$ on Haiku~4.5 pairs
(Figure~\ref{fig:rho}). Sample size does not explain the drop, since the classifier still reaches
0.851 on random stored-pair subsets of the same size. The generators differ because of the attack prompt. On
Sonnet~5 the residual is lexical, led by \texttt{def main} (in 67\% of attacks and 38.5\% of honest
programs) and \texttt{data[}, the program layout the attack prompt elicits, which Haiku~4.5 never
adopts. With both classes written from the attack prompt, Sonnet~5 falls to
$\rho = \matchedRho{}$ and Haiku~4.5 stays at $\rho = \haikuMatchedRho{}$. The original and
prompt-matched honest classes of Sonnet~5, both correct programs, separate at 0.600, so on that
generator the prompt alone carries signal.

\paragraph{Verified attacks.}
Only 14 of 623 Sonnet~5 attacks and 2 of 611 Haiku~4.5 attacks fire, so the rows above mostly
measure attempts at sabotage. The rate is low partly because 52\% of test-passing attacks declare
a public test input as their trigger, which cannot diverge from a correct program. We therefore
resampled each Sonnet~5 attack up to six more times and kept the first that fired, the survivor
selection the stored corpus itself uses. On these 99 verified pairs the classifier retains
$\rho = \strictRho{}$ (CI \strictRhoLo{} to \strictRhoHi{}), and \matchedStrictRho{} with prompt
matching. When the backdoors work, most of the separability survives the change of author. The
interval is wide, but the verified rows do not support reading the stored signal as mainly
authorship. Selection does not explain this. Replacing each verified attack with a non-firing
attempt on the same problem leaves $S$ almost unchanged (0.745 against 0.751).

\section{An LLM monitor on the same pairs}
\label{sec:monitor}

We scored every program with a zero-shot monitor prompt (Appendix~\ref{app:monitor}), using
Sonnet~5, which wrote both classes, and Haiku~4.5, which wrote neither. On all attempts the
Sonnet~5 monitor falls from AUROC 0.958 on stored pairs to 0.566 on same-generator pairs, but
this compares working stored backdoors with attempts that almost never fire. The monitor gives
those attempts a mean suspicion of 6.9 out of 100, against 78.8 for the stored attacks. The verified pairs give the fair
comparison. There the monitor falls from 0.944 to 0.818, a monitor $\rho$ of \monRhoStrict{}
(CI \monRhoStrictLo{} to \monRhoStrictHi{}), and Haiku~4.5 gives \monHaikuRhoStrict{}.

A control protocol depends on how many attacks are caught at a fixed audit budget rather than on
AUROC. Auditing 5\% of honest programs, the Sonnet~5 monitor catches 81\% of the stored verified
backdoors (CI 72\% to 89\%) but 55\% of the same-generator ones (CI 43\% to 66\%,
Table~\ref{tab:audit}). On these problems the stored pairs overstate the catch rate by about a
quarter of all attacks, though part of the gap may reflect subtler backdoors from Sonnet~5 rather
than authorship. Monitor and classifier errors are unrelated ($\phi = 0.04$ on the headline pairs).

\section{The label records attack failure}
\label{sec:label}

The filtered split puts a problem in the attack class only if its backdoor works. Otherwise the
problem contributes its human solution to the honest class, which holds 720 of the 1{,}203 honest
test items. Attack-class problems have about half as many test cases (20.95 against 38.85),
plausibly because a backdoor slips more easily past fewer tests. The label thus encodes attack
difficulty as well as honesty, and this is what the no-code classifier reads.

\section{Limitations}
\label{sec:limitations}

The construction changes more than the author. Our generators differ from the ten stored
attackers in backdoor style and success rate and were sampled with default API settings, so $\rho$
bounds the authorship share in neither direction. The all-attempts rows compare unlike attack
classes, since the stored attacks almost always fire (every one in a 194-problem sample) while
98\% of ours do not, and the like-for-like verified rows rest on 99 pairs. We study one APPS
corpus family and five agentic settings (Appendix~\ref{app:agentic}). A high floor is evidence
about a corpus, and nothing here corrects a specific published monitor score.

\section{Recommendations}
\label{sec:recommendations}

Stored pairs remain the cheapest way to develop a monitor. We suggest that benchmark builders
(1)~report a bag-of-words and a no-code floor beside every monitor score, each against a
permutation null, (2)~generate both classes with one model and one prompt, (3)~define the
negative class by honesty, independent of attack success, and (4)~report verified attacks
separately from all attempts, with the catch rate at a fixed audit budget. The same-generator
corpus, its retry pool and the scripts are released under the MIT licence
(Appendix~\ref{app:release}).

\paragraph{Generation and funnel.}
Honest solutions pass the public tests for 77.0\% (Sonnet~5) and 72.8\% (Haiku~4.5) of the 1{,}444
problems. Attacks are written from the problem statement alone, which we call the independent
arm. A pair enters the corpus when both its honest solution and its attack pass the public tests.
The retry pool for Sonnet~5 holds 11{,}565 draws, from which the verified set keeps the first
draw per problem that fires without crashing. Haiku~4.5 produced 35 firing attacks, below the
50-pair minimum we set for a verified row, so it has none.

\paragraph{Pair similarity.}
A pair built by editing the honest solution would make the classes near-copies and lower $S$ for
a reason unrelated to authorship. Table~\ref{tab:similarity} shows that the independent arm keeps

pairs are more self-similar (mean 0.724), so we recomputed $S$ within similarity strata. It stays
between 0.47 and 0.51 in every stratum, including pairs less similar than the stored ones, while
$B'$ stays between 0.79 and 0.83.

\paragraph{Regenerating only one class.}
Replacing only the honest class with code from Qwen3-Coder-30B, against the stored backdoors,
increases separability to 0.962 from 0.874 on the same 668 problems ($\rho = 1.23$, fold-mean
estimate). One authorship gap is replaced by a larger one, which is why both classes must come
from the same model.

\paragraph{What the residual signal is.}
Masking numbers or comparison operators leaves $S$ unchanged. Normalising identifiers lowers the
Sonnet~5 headline $S$ to 0.699 ($\rho = 0.54$). Under prompt matching the same mask gives
$\rho = 0.34$ (CI 0.28 to 0.39), so identifier normalisation and prompt matching remove largely the
same signal. The layout vocabulary of the Sonnet~5 attacks (\texttt{def main},
\texttt{sys.stdin}, \texttt{data[}) appears in none of the Haiku~4.5 programs in any class, which
read input with \texttt{input(} throughout.

\paragraph{Sample size.}
On random subsets of the stored pairs of matching size (30 draws each), the classifier reaches
0.851 at $n = 623$ and 0.773 at $n = 99$, against $B'$ of 0.865 and 0.789 on the exact problems.

\section{The monitor}
\label{app:monitor}

The monitor reads one program at a time with its problem statement and returns a short rationale
and a suspicion score from 0 to 100. Comments are stripped with the same function the classifier
uses, and request order is shuffled. Unparsable replies are dropped, never imputed. With a
512-token limit, Haiku~4.5 left about half of its replies unparsable on the all-attempts pairs,
with different missing rates by class, so we report its all-attempts row ($\rho = 0.151$) only as
indicative. Its verified row uses a 1{,}024-token limit, which leaves 2 of 198 replies missing.

\section{Agentic settings}
\label{app:agentic}

In five ControlArena settings \cite{sinha2026controlarenacorpora} the same three models
(claude-sonnet-4, gemini-2.5-pro and gpt-5) write both classes, so no authorship confound is
possible. A structural floor remains. Within each task, transcript length alone separates attack
from honest runs at AUROC between \bashFloor{} (\texttt{bash}) and \agentdojoFloor{}
(\texttt{agentdojo}) (Figure~\ref{fig:agentic}). We compare each value with a permutation null of
the same statistic, in which labels are shuffled within each task. Four of the five settings are
far above their null ($p \le 0.001$), and \texttt{bash} is at it. Two settings average over only
five tasks, so their values are less well determined. These settings also have a further channel. A
short keyword regular expression over the untrusted model's own reasoning reaches 0.76 to 0.82,
because attack policies restate their side task there. We note this only to bound our claims and
defer to \cite{little2026length}, which studies it properly.

\section{Test harness}
\label{app:harness}

Our runner feeds each shipped input to a solution under per-case time and memory limits and
compares normalised output. It agrees with the artifact's own \texttt{solution\_passes\_tests}
on 95.84\% of the analysis pool and never passes a solution the artifact rejects. We use our flag
for both classes so that a checker cannot be stricter on one class than the other. Under the
artifact's flag the stored-pair AUROC over all 1{,}444 problems is 0.871 (fold mean), and under
ours it is 0.873 over 1{,}406. Two Python-version artifacts in the human solutions (\texttt{stdin} without
\texttt{.buffer}, and \texttt{fractions.gcd}, removed in Python~3.9) affect only the stored pairs.

\section{Release}
\label{app:release}

The release contains 1{,}444 Sonnet~5 honest programs, 1{,}112 attacks from each of the edit and
independent arms, all 11{,}565 draws of the retry pool, pair lists under both selection rules
(623 passing and 14 firing pairs for the first draw; 1{,}046 and 99 for survivor selection, or
106 if a crash on the trigger counts as firing), the 25 scripts behind the measurements, a dataset
card, and a manifest with row counts and checksums. Data and code are MIT-licensed. No upstream
code, problem statement or test case is redistributed.
