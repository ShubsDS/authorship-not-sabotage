\begin{abstract}
Monitors for AI control are developed and ranked on stored pairs of programs, in which each
programming problem has an honest solution and a solution that hides a backdoor. In the public
corpora used for this, people wrote the honest solutions and language models wrote the backdoors,
so a monitor can separate the two classes by recognising who wrote the code. We measure how much of
the benchmark signal this difference in authorship explains. A lexical classifier that has no way to
detect a backdoor reaches an AUROC of \lexFloor{} on the standard filtered split, and a classifier
that reads only problem metadata reaches \metaFloor{}; both outscore \monBelow{} of the \monN{}
monitors published for that split. We then rebuild the corpus so that one model writes both
solutions to every problem. The lexical classifier keeps between 10\% and 69\% of its separability
above chance on the rebuilt pairs, and less when both classes share a prompt, but most rebuilt
backdoors never work. On the 99 that do, it keeps 86\%, and a monitor that audits 5\% of honest
programs catches \catchRebuilt\% of them against \catchStored\% of the stored backdoors for the
same problems. Stored pairs therefore overstate how well monitors catch backdoors, although
authorship is unlikely to be the only reason. We release the rebuilt corpus and propose changes to
how such benchmarks are built and reported.
\end{abstract}

\section{Introduction}

AI control studies how to deploy a capable model that may try to cause harm, using safeguards that
continue to work if it does \cite{greenblatt2023aicontrol}. The safeguard most protocols rely on is
trusted monitoring, in which a weaker model that is trusted reads each output of the untrusted model
and sends the most suspicious ones to a human for audit \cite{greenblatt2023aicontrol,
korbak2025evaluate}. The protection this offers depends on how reliably the monitor tells sabotage
from honest work, and for code that is usually measured on stored pairs. These are fixed corpora in
which every programming problem comes with an honest solution and a solution containing a backdoor,
and recent work uses them to tune monitors, to compare dozens of candidate monitors and to choose
ensembles \cite{koran2026ensemble, terekhov2025controltax, jha2026decorrelation}.

The stored pairs in current use were assembled in a way that leaves a second difference between the
classes. Their honest solutions come from the APPS dataset \cite{hendrycks2021apps} and were written
by people, while every backdoor was written by a language model (Figure~\ref{fig:schematic}). People
and models write code differently, and simple classifiers can tell them apart
\cite{caliskan2015stylometry, suh2025detecting, orel2026aicd}. Benchmarks elsewhere in machine
learning have been solved through differences of this kind, from the wording of hypotheses in
natural language inference \cite{gururangan2018annotation} to hospital markers in chest
radiographs \cite{zech2018pneumonia}. A monitor ranked on stored pairs could therefore score well in
part because it recognises code written by a model. The standard split removes comments and keeps
only working solutions \cite{koran2026ensemble}, which erases the most visible traces of authorship
while leaving the authors themselves unchanged.

We measure how much of the signal in stored pairs comes from authorship, with three experiments.
First, we fit two classifiers that cannot detect a backdoor, one on the words in the code and one on
three properties of the problem, and compare them with the 24 monitors published for the standard
split. Both outscore 20 of the monitors, and the evidence points to the authors of the code as the
source of their signal (Section~\ref{sec:floors}). Second, we rebuild the corpus so that a single
model writes both solutions to each problem, and ask how much separability survives when the author
no longer differs. For the attempted backdoors that the benchmark's rules admit, much of it
disappears, but almost all of those attempts are inert. On the smaller set of backdoors that
actually work, more of it survives, largely because authorship contributes least on the problems
where a working backdoor can be written at all (Section~\ref{sec:rebuilt}). Third, we
evaluate an LLM monitor on both kinds of pair at a fixed audit budget, the quantity a control
protocol depends on, and find that stored pairs overstate how many working backdoors it catches by
about a quarter of all backdoors.

Authorship is therefore a large signal in the stored corpora but not the only one, and on working backdoors much of the stored signal survives when the author is held fixed. We also find that the standard split defines its honest class partly by which attacks failed. We close with four changes to how stored pair benchmarks are built and reported (Section~\ref{sec:discussion}) and release the rebuilt corpus with the scripts behind every number in this paper.

\section{Related work}
\label{sec:related}

Control evaluations were introduced with a trusted monitor that inspects APPS solutions for
backdoors \cite{greenblatt2023aicontrol}, and the framework has since been formalised as a game
\cite{griffin2024games}, extended to adaptive deployment \cite{wen2024adaptive} and to agents
\cite{korbak2025evaluate, kutasov2025shadearena, bhatt2025ctrlz}, and implemented in ControlArena
\cite{controlarena}. Related evaluations ask whether models can sabotage \cite{benton2024sabotage}
or plan subversion \cite{mallen2024subversion}, and whether monitors that read a model's reasoning
remain reliable \cite{baker2025monitoring, korbak2025monitorability, arnav2025cotredhanded}. Work on
monitors themselves compares ensembles on a filtered APPS backdoor corpus \cite{koran2026ensemble,
jha2026decorrelation} and studies adaptive attacks \cite{terekhov2026adaptive}, attack selection
\cite{gewang2026attackselection}, calibration across model families \cite{pinto2026calibration} and
legibility \cite{sreevatsa2026legibility}. Most of these studies generate honest and attack behaviour
from the same model at evaluation time. The stored APPS corpora are the main exception, and they are
the subject of this paper.

Our analysis belongs to a longer tradition of finding that a benchmark can be solved without the
ability it was meant to measure. Classifiers that see only the hypothesis solve much of natural
language inference \cite{gururangan2018annotation, poliak2018hypothesis, mccoy2019right}, reading
comprehension can often be answered without the passage \cite{kaushik2018howmuch}, and image models
have learned to diagnose from scanner and hospital artefacts \cite{zech2018pneumonia,
degrave2021covid}. These behaviours are known as shortcut learning \cite{geirhos2020shortcut} or
Clever Hans effects \cite{lapuschkin2019cleverhans, pacchiardi2024cleverhans}, and they follow from
how datasets are assembled \cite{torralba2011unbiased, recht2019imagenet}. A baseline that sees only part of the input
that fails does not prove a dataset clean \cite{feng2019misleading}, so we pair baselines with a
construction that removes the confound directly. Reviews of evaluation practice document similar
problems across machine learning \cite{kapoor2022leakage, liao2021learning, raji2021everything,
bowman2021fix, reuel2024betterbench} and in code benchmarks specifically
\cite{aleithan2024swebenchplus, wang2025solvedissues, zhou2025lessleak}.

The confound we study is also the target of a separate literature. Programmers can be identified
from their coding style \cite{caliskan2015stylometry}, and code written by language models can be
detected with trained classifiers \cite{nguyen2024gptsniffer}, statistics of model likelihood
\cite{mitchell2023detectgpt, yang2023zeroshot} and simple lexical features \cite{suh2025detecting,
orel2026aicd}. Benchmarks for that task match their classes on problem and length
\cite{guo2025codemirage, demirok2025multiaigcd}, a practice backdoor benchmarks have not adopted.

\section{Setup}
\label{sec:setup}

\subsection{Stored pairs and two blind baselines}

We study an APPS backdoor corpus of 5{,}000 problems \cite{inglis2025appscontrolarena}. Its honest
solutions come from APPS and its backdoors from ten language models, among them o3-mini, Claude~3.7
Sonnet and GPT-4o. The standard split filters this corpus \cite{koran2026highquality,
koran2026ensemble}. Each of its 1{,}209 training problems contributes one honest and one backdoored
solution, and its test set holds 1{,}375 programs, one per problem, of which 172 are backdoored. A
test problem is labelled backdoored only if its backdoor works, and comments are removed from all
code. We rebuild the split with the released harness and compare against the published scores of 24
open weight monitors on its test set \cite{jha2026decorrelation}.

Neither of our baselines has any representation of program behaviour. The \emph{lexical classifier}
is a logistic regression on the frequencies of words and word pairs in the code, weighted by inverse
document frequency. The \emph{metadata classifier} is a logistic regression on the difficulty of the
problem, its number of test cases and the length of its statement, and never reads the code.

\subsection{Rebuilding the corpus with one author}

We rebuild the corpus on the 1{,}444 problems that have a passing human solution, a working stored
backdoor and deterministic tests, using Claude Sonnet~5 and Claude Haiku~4.5. For each problem the
model writes an honest solution and, in a separate request that sees only the problem, a solution
with a hidden backdoor together with an input meant to trigger it. We draw one attempt per problem
before seeing its outcome and run every program through our own test harness
(Appendix~\ref{app:harness}). Following the benchmark, an attempt joins the attack class if it
passes the public tests. We call a backdoor \emph{working} if, on its trigger input, it returns a
different answer from the same model's honest solution. In a \emph{shared prompt} variant, the honest
solution is requested with the attack prompt itself, its request for a flaw replaced by a request for
a correct program, so that the two classes also receive the same instructions.

\subsection{Measuring what survives}

Let $S$ be the lexical classifier's AUROC on rebuilt pairs and $B'$ its AUROC on the stored pairs of
the same problems. We report the share of separability above chance that survives a change of
author,
\[
  \rho = \frac{S - 0.5}{B' - 0.5},
\]
which is 1 when holding the author fixed changes nothing and 0 when it removes the whole signal. Both
AUROCs come from five folds split by problem, and all intervals are 95\% intervals from 2{,}000
bootstrap samples of problems, drawing $S$ and $B'$ together for $\rho$. Before generating any data
we fixed two thresholds for reading $\rho$, treating values up to 0.33 as mostly authorship and
values above 0.72 as mostly content. The rebuilt attacks differ from the stored ones in style and in
how often they work, as well as in author, so $\rho$ describes this particular construction rather
than isolating the causal effect of authorship (Section~\ref{sec:discussion}).

On the filtered test split the lexical classifier reaches an AUROC of \lexFloor{} (95\% interval
0.770 to 0.841), and the metadata classifier reaches \metaFloor{} under cross validation within the
test set. Both are far above their permutation nulls, whose 95th percentiles are 0.547 and 0.555,
and both outscore \monBelow{} of the \monN{} published monitors, whose median AUROC is \monMedian{}
(Figure~\ref{fig:floors}). The lexical classifier's advantage over 18 of those monitors survives a
paired bootstrap. The comparison is between classifiers fitted on benchmark data and monitors that
are only prompted, so it measures how much the corpus gives away without any detection of sabotage,
and it does not suggest that a word count would make a better monitor. The metadata result is also
less secure than the lexical one. On a single held out slice of the test set it falls to
\metaHeldout{}, close to its own null, so we treat it as a diagnostic of how the split was labelled
(Section~\ref{sec:label}) and use the lexical classifier as our main baseline.

Several observations show that the lexical classifier is reading authorship more than sabotage. Trained on the backdoors written by one attacker model, it identifies those written by another with a pairwise accuracy of 0.969, so it has learned something the attackers share. It separates inert backdoors, which never change a program's output, almost as well as working ones (0.879 against 0.935), although an inert backdoor gives a sabotage detector nothing to find. Its weights show what it uses instead (Figure~\ref{fig:features}a). On the backdoored side the strongest features are \texttt{and}, \texttt{==} and \texttt{if}, the tokens of an added special case, which inert backdoors contain as well. On the honest side they are the idioms of people writing competitive programs, such as \texttt{for i}, \texttt{while} and bare calls to \texttt{input}. Style markers of the model are just as visible in the raw programs (Figure~\ref{fig:schematic}). The entry point guard \texttt{\_\_main\_\_} appears in 152 of the 1{,}209 backdoored training solutions and in one honest solution. Removing comments does remove the channel it targets, since a detector that counts \texttt{\#} characters falls from 0.696 to chance, but it leaves these differences untouched.

\subsection{The label records which attacks failed}
\label{sec:label}

The split's labels add a second shortcut. A test problem is placed in the backdoored class only if
its backdoor works, and when the backdoor fails the problem contributes its human solution to the
honest class instead. Of the 1{,}203 honest test programs, 720 entered the split this way, so the
honest class consists largely of problems that the attackers failed on. Those problems differ
systematically from the rest. Problems in the backdoored class have about half as many test cases,
20.95 against 38.85 on average, plausibly because a backdoor is easier to hide from fewer tests. The
label therefore depends on how hard each problem was to attack, and that dependence is what the
metadata classifier exploits.

\label{sec:rebuilt}

\subsection{The lexical classifier}

When one model writes both classes, the lexical classifier keeps $\rho = \rhoSonAll{}$ of its
separability on Sonnet~5 pairs and $\rho = \rhoHaiAll{}$ on Haiku~4.5 pairs
(Figure~\ref{fig:rebuilt}a). The drop is not a matter of sample size, because on random subsets of
the stored pairs with the same number of problems the classifier still reaches 0.851. The two models
differ because they respond differently to the attack prompt. Asked for a backdoor, Sonnet~5
switches to a layout built around \texttt{def main} and a \texttt{data} list read from standard
input (Figure~\ref{fig:features}b), with \texttt{def main}
in 67\% of its backdoored programs and 38.5\% of its honest ones, while Haiku~4.5 never uses it in
either class. Giving both classes the attack prompt tests this directly. Sonnet~5 then falls to
$\rho = \rhoSonShared{}$ and Haiku~4.5 stays at $\rho = \rhoHaiShared{}$. On Sonnet~5 the prompt
carries signal on its own, since its original and shared prompt honest solutions, both correct, can
be told apart with an AUROC of 0.600.

\subsection{Working backdoors}

The comparison so far has a limitation. Only 14 of the 623 Sonnet~5 attempts and 2 of the 611
Haiku~4.5 attempts work, so the comparison above is mostly about attempted sabotage. Part of the
reason is the protocol. Of the attempts, 52\% name a public test case as their trigger, and a program
that passes the public tests cannot give a different answer on one of them. To obtain working
backdoors we resampled each Sonnet~5 attempt up to six more times and kept the first that worked,
which is also how the stored corpus selected its own backdoors. On these 99 pairs the classifier
keeps $\rho = \rhoSonVer{}$ (95\% interval \rhoSonVerLo{} to \rhoSonVerHi{}), and \rhoSonVerShared{}
with a shared prompt, so on working backdoors most of the stored separability survives a change of
author. This higher ratio comes from the stored side of the comparison. The classifier does no better on rebuilt pairs here than before,
with an AUROC of 0.749 against 0.750, and replacing each working backdoor with a failed attempt on
the same problem barely moves it (0.745 against 0.751). What changes is the stored side. On the
problems where a working backdoor could be produced, the stored pairs are themselves harder to tell
apart, with $B'$ at 0.789 against 0.865 on the full set. Authorship therefore contributes least on
exactly the problems where sabotage is feasible, and the headline ratio partly reflects which
problems enter the comparison.

\subsection{An LLM monitor at a fixed audit budget}

We gave every program to a prompted monitor (Appendix~\ref{app:monitor}), using Sonnet~5, which
wrote both classes, and Haiku~4.5, which wrote neither. Across all attempts the Sonnet~5 monitor
falls from an AUROC of \storedMonSonAll{} on stored pairs to \rebuiltMonSonAll{} on rebuilt pairs,
but most of that fall reflects attempts with nothing to find (Figure~\ref{fig:scores}). The monitor gives them a mean suspicion
of 6.9 out of 100, against 78.8 for the stored backdoors. On working backdoors the fall is smaller,
from \storedMonSonVer{} to \rebuiltMonSonVer{} ($\rho = \rhoMonSonVer{}$), and the Haiku~4.5 monitor
shows a similar ratio of \rhoMonHaiVer{} (Appendix~\ref{app:monitor}). The monitor's errors are unrelated to the classifier's
($\phi = 0.04$ across pairs), so the two respond to different properties of the code.

A control protocol does not use a monitor's AUROC. It audits a fixed share of the untrusted model's
outputs and depends on how many backdoors fall inside that share. Figure~\ref{fig:rebuilt}b fixes the
share of honest programs that are audited. At a 5\% budget, the Sonnet~5 monitor catches
\catchStored\% of the stored working backdoors (95\% interval \catchStoredLo\% to \catchStoredHi\%)
and \catchRebuilt\% of the rebuilt ones (\catchRebuiltLo\% to \catchRebuiltHi\%), and the gap
persists at every budget up to 20\%. A safety estimate taken from stored pairs would therefore
overstate this monitor's catch rate by about a quarter of all backdoors. Some of the gap may reflect
Sonnet~5 writing subtler backdoors than the stored attackers rather than authorship, and this
comparison cannot separate the two.

\section{Discussion}
\label{sec:discussion}

Stored pairs are cheap and reproducible, and our results do not argue against using them. They do
show that a score on stored pairs mixes the detection of sabotage with the recognition of authors
and of problem difficulty, strongly enough that classifiers blind to program behaviour outscore
most published monitors.

Our estimates come with limitations. Rebuilding the corpus changes more than the author, because our
two models differ from the ten stored attackers in how they write backdoors and how often those
backdoors work, and we sampled them through an API with default settings and without extended
thinking. As a result $\rho$ is neither an upper nor a lower bound on the share of signal due to
authorship. The comparison over all attempts sets stored backdoors that almost always work (all of
those we checked, in a sample of 194 problems) against rebuilt attempts that mostly do not. The
comparison on working backdoors avoids this but rests on 99 pairs and one generator. We study one
family of APPS corpora and five agentic settings in which the same models write both classes and a
weaker structural baseline remains (Appendix~\ref{app:agentic}). Finally, a strong baseline is
evidence about a corpus, and none of our results corrects a specific published monitor score.

We suggest four changes for stored pair benchmarks. Report a lexical and a metadata baseline beside every monitor score, each against a permutation null. Have one model write both classes from one prompt. Define the honest class by honesty, independently of whether attacks on a problem succeeded. And report working backdoors separately from all attempts, with the catch rate at a fixed audit budget. The rebuilt corpus, its retry pool and the scripts are released under the MIT licence (Appendix~\ref{app:harness}).

\paragraph{Yield.}

\paragraph{Rebuilding only one class.}
Replacing only the honest solutions with code from Qwen3-Coder-30B, against the stored backdoors,
raises the AUROC on the same 668 problems from 0.874 to 0.962 ($\rho = 1.23$, a mean over folds).
This swaps one difference in authorship for a larger one, which is why both classes must come from
the same model.

\paragraph{What the remaining signal is.}
Masking numbers or comparison operators leaves the Sonnet~5 AUROC unchanged. Normalising
identifiers lowers it to 0.699 ($\rho = 0.54$). With a shared prompt the same mask gives
$\rho = 0.34$ (0.28 to 0.39), so identifier normalisation and a shared prompt remove largely the
same signal. The layout that marks Sonnet~5 backdoors (\texttt{def main}, \texttt{sys.stdin},
\texttt{data[}) appears in none of the Haiku~4.5 programs, which read input with \texttt{input()}
throughout.

\paragraph{Sample size.}
On 30 random subsets of the stored pairs, the classifier reaches 0.851 with 623 problems and 0.773
with 99, against stored AUROCs of 0.865 and 0.789 on the exact rebuilt problems.

\section{The LLM monitor}
\label{app:monitor}

The monitor sees one program at a time together with its problem statement, writes a short
rationale and ends with a suspicion score from 0 to 100. Comments are removed with the same
function the classifier uses, and requests are shuffled. Replies without a score are dropped. With
a limit of 512 output tokens, Haiku~4.5 left about half of its replies without a score on the full
set of attempts, at different rates for the two classes, so we omit that row. Its row for working
backdoors uses a limit of 1{,}024 tokens, which leaves 2 of 198 replies without a score.

\section{Agentic settings}
\label{app:agentic}

In five ControlArena settings \cite{sinha2026controlarenacorpora}, the same three models
(claude-sonnet-4, gemini-2.5-pro and gpt-5) produce both honest and attack transcripts, so there is
no difference in authorship. A structural baseline still separates the classes. Within each task,
transcript length alone reaches an AUROC between 0.504 (bash) and 0.802 (agentdojo)
(Figure~\ref{fig:agentic}). A permutation null of the same statistic, shuffling labels within each
task, puts four of the five settings far above chance ($p \le 0.001$) and leaves bash at chance. In these settings a
short keyword search over the untrusted model's own reasoning also reaches 0.76 to 0.82, because
attack policies restate their side task there. We mention this only to bound our claims and refer
to \cite{little2026length} for a proper treatment.

\section{Test harness and release}
\label{app:harness}

Our harness runs each solution on every shipped test input under limits on time and memory and
compares normalised output. It agrees with the corpus's own \texttt{solution\_passes\_tests} on
95.84\% of the 1{,}444 problems and never passes a solution the corpus rejects. We use our verdict
for both classes, and the stored AUROC barely changes with it (0.871 under the corpus's verdict,
0.873 under ours).

scripts behind our measurements and a manifest with checksums. No upstream data is redistributed.
