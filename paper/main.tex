\begin{abstract}
AI-control monitors are tuned and ranked on stored pairs, an honest and a backdoored solution to
each programming problem. In APPS-backdoor corpora the honest code is human-written and the
backdoor model-written, so a detector can separate them without reading any backdoor. On the
filtered, comment-stripped split, bag-of-words reaches AUROC \tfidfKoran{}, transfers across
attacking models, and is nearly as strong on backdoors that never work. A classifier reading
only problem metadata reaches \nocodeCV{}; it reads how the label was selected, not the code. We
rebuild the corpus with one model writing both classes on the same problems and one harness
verifying both, and release it.\footnote{Code and corpus:
\url{https://github.com/ShubsDS/authorship-not-sabotage}.} Writer features then cannot separate
the classes; what still does comes from what the prompts asked for, the backdoor included. The
surviving share of stored-pair separability, $\rho$, is \sameGenRho{} (Sonnet~5) and
\haikuRho{} (Haiku~4.5) on attempts, of which \relFireFirst{} of \sameGenN{} and
\haikuFireInRow{} of \haikuN{} fire, and \strictRho{} on \strictN{} Sonnet attacks that fire.
$\rho$ is not the backdoor's share: the attacks change with the writer, and the attacking model
alone moves stored-pair AUROC from \bAttackerLo{} to \bAttackerHi{}. A Sonnet~5 monitor falls
from \monStoredHeadAbs{} to \monitorS{} on our pairs; swapping one class at a time puts the whole
drop in our attacks, which it finds far less suspicious. Evaluations should report both
classifiers as floors against permutation nulls, build both classes with one model under one
prompt, define the negative class by honesty, and report detection at a fixed audit budget with
the firing rate.
\end{abstract}

\section{Introduction}

The backbone protocol of AI control is trusted monitoring, where a weaker trusted model reads
an untrusted model's output and flags sabotage \cite{greenblatt2023aicontrol}. Monitors
are developed, tuned and ranked almost entirely on \emph{stored} honest/attack pairs, fixed
corpora in which each programming problem contributes an honest solution and a solution
carrying a planted backdoor \cite{koran2026ensemble, terekhov2025controltax,
jha2026decorrelation}. Honest solutions are
human-written, taken from APPS \cite{hendrycks2021apps}, and backdoors are written by language
models, so a detector can separate the classes without reading any backdoor.

There are known confounding variables between human and AI solutions, such as commenting style, so corpora are often preprocessed to mitigate them. The filtered
release keeps only working honest solutions and working backdoors and strips every comment
\cite{koran2026ensemble}; Control Tax reports its pass-tests pre-filter and moves its failed
backdoors to an appendix \cite{terekhov2025controltax}; the monitor-ensemble harness of
\cite{jha2026decorrelation} ships a \texttt{--leak-check} flag with two trivial baselines: a
\texttt{\#}-count detector that falls from \hashRaw{} to \hashStripped{} once comments
are stripped, and code length alone, at \lenFiltered{}. Outside AI control, bag-of-words is known to separate human-written from
model-written code \cite{orel2026aicd}, and the benchmarks built for that task match their two
classes on line and character count or on shared problem definitions \cite{guo2025codemirage,
demirok2025multiaigcd}. Adjacent control work attacks other axes: monitors subverted with
injected text, attacker-side selection shown to inflate safety estimates, transcript length
removed as a nuisance covariate \cite{terekhov2026adaptive, gewang2026attackselection,
pinto2026calibration}.

Two classifiers separate the classes of the filtered, comment-stripped split without reading a
backdoor. Bag-of-words reaches AUROC \tfidfKoran{}, above \tfidfKoranCount{} of the \monN{}
open-weight monitors ranked on that split. It transfers across backdoor generators and is
nearly as strong on backdoors that never produce a wrong answer as on working ones, so it is not
reading the sabotage. A classifier that reads no code,
only problem difficulty, test count and question length -- the \emph{no-code floor} -- reaches
\nocodeCV{}, above \nocodeCVCount{} of the monitors. It reads how the label was selected:
attack problems carry fewer tests.

We contribute (i)~two classifier floors for stored-pair corpora, bag-of-words and no-code, each
against a permutation null; (ii)~a same-generator construction, in which one model writes both
classes on the same problems and one harness verifies both, and the corpus that implements it;
and (iii)~a label artifact: labelling by \texttt{backdoor\_works} defines the negative class by
attack failure, so the negative class records which attacks failed. They imply a reporting
practice: both floors beside any monitor score, both classes from one model under one prompt, a
negative class defined by honesty, and detection at a fixed audit budget reported with the
share of attacks that fire. Our claims concern monitor training, selection and benchmarking on
stored pairs, and our measurement is of one APPS-derived family plus five agentic settings
(appendix~\ref{app:agentic}). ControlArena, the evaluation framework most of these corpora are
exported from, generates both classes live and is not implicated.

\section{Setup}

\begin{figure}[t]\centering

We use seven public corpora, whose
per-class provenance is the object of study: two views of one APPS-backdoor artifact
(appendix~\ref{app:schema}) and five agentic settings (appendix~\ref{app:agentic}). In the
APPS family the honest class is human and the
attacks come from \storedAttackers{} named models or an unattributed source. Six of the seven
declare no licence \cite{koran2026highquality, sinha2026controlarenacorpora}, so we report only
aggregates and redistribute none.

Our primary protocol is the filtered, comment-stripped split
\cite{koran2026ensemble}: \splitTrain{} train problems (\splitTrainItems{} paired items) and
\splitTest{} test items (\splitAttack{} attack, \splitHonest{} honest), labelled by
\texttt{backdoor\_works}, reconstructed with the released harness code
\cite{jha2026decorrelation}. The split is a filtered view of a \baselineBn{}-problem artifact
whose full pool the same-generator arms use; on that pool the stored pairs give
$B = \baselineB{}$ (Figure~\ref{fig:constructions}). Generated code is scored by our own
runner, applied to both classes (appendix~\ref{app:harness}).

Against that we build a corpus in which one model, Sonnet~5 or Haiku~4.5, writes both classes
on the same APPS problems. With one writer, writer features cannot separate the classes; what
still separates them comes from what the two prompts asked for, the backdoor included. The
\emph{independent} arm writes the attack class from the problem statement alone. An \emph{edit}
arm, shown its own honest solution, returns near-copies (appendix~\ref{app:pairsim}), and a
\emph{prompt-matched} arm regenerates the honest class from the attack prompt with the clauses
asking for a flaw replaced by their correct-program counterparts, so both classes are elicited
alike. A backdoor \emph{fires} if it passes the public tests and gives a wrong answer on the
trigger input the attacker declares; one that never fires is \emph{inert}. \emph{Headline} rows
(Table~\ref{tab:gates}) are attempts: one independent-arm attack per problem, sampled before
its outcome is known and kept if it passes the public tests; \emph{strict} rows keep only
attacks that fire, drawn from a pool of retries.

The rebuild changes the attacks as well as the writer: ours rarely fire, and a monitor finds
them far less suspicious than the stored ones (\S\ref{sec:results}). $\rho$
(Table~\ref{tab:notation}) is therefore the share of stored-pair separability that survives, not
the share due to the backdoor nor a bound on it. Table~\ref{tab:gates} reports the
share of joint-bootstrap draws with $\rho > \rhoContent{}$; that line and $\rho = \rhoCollapse{}$
were fixed before any arm ran.

\section{Results}
\label{sec:results}

Comment stripping drives comment count and code length to chance
(Table~\ref{tab:protocol-baseline}). Two other baselines do not move; we call them
\emph{floors}: a monitor at or below a floor has shown nothing beyond what the
corpus leaks. On the filtered, comment-stripped split, bag-of-words reaches AUROC
\tfidfKoran{}, above \tfidfKoranCount{} of the \monN{} monitors ranked on it, and the
no-code floor reaches \nocodeCV{}, above \nocodeCVCount{}; both are far above permutation
nulls (Figure~\ref{fig:monitors}, appendix~\ref{app:protocol}). The floors are
trained (bag-of-words on the split's train problems, the no-code floor cross-validated within
the test split) and the monitors are zero-shot, so the comparison states what the corpus makes
recoverable, not which is the better monitor. The no-code floor reads only problem metadata,
so it measures how the label was selected, not authorship.

Three further measurements show that the bag-of-words classifier is not reading the backdoor
(pairwise accuracies for the first two; appendix~\ref{app:protocol}). It transfers across
backdoor generators at \transfer{}, so the feature it has learned is one the attackers share.
It is nearly as strong on inert backdoors, the harder case for a detector of sabotage, as on
working ones (\pairInert{} against \pairWorking{}). What it reads is stylistic:
\texttt{\_\_main\_\_} appears in 0.116 of attack samples against 0.000 of honest ones, a gap
that replicates on the train split (152 against 1 of \splitTrain{} per class). All three are
on comment-stripped code (unstripped: appendix~\ref{app:stripped}); a token-level version of
the last test does not replicate (appendix~\ref{app:token}).

The split selects on a second property besides authorship. Labelling by
\texttt{backdoor\_works} defines the negative class by attack failure rather than by
honesty: \inertShare{} of the test split's labelled backdoors do not work, and a
problem whose backdoor fails contributes its human honest solution instead, so the label is
set before any code is read. Attack problems also carry half as many test cases
(\testCasesAttack{} against \testCasesHonest{}), which the no-code floor reads.

Table~\ref{tab:gates} gives $\rho$ for each arm. On the headline rows, holding the writer
constant leaves $\rho = \sameGenRho{}$ for Sonnet~5 and \haikuRho{} for Haiku~4.5; sample size
does not account for the fall (appendix~\ref{app:robust}). Only \relFireFirst{} of Sonnet~5's
\sameGenN{} attacks and \haikuFireInRow{} of Haiku~4.5's \haikuN{} fire, while every stored

The two generators respond differently to the attack prompt. On Sonnet~5 what survives is
lexical: of the feature-ablation masks only identifier normalisation moves $S$
(appendix~\ref{app:robust}), and the top attack-side features, \texttt{def main}
(\defMainAttack{} of attack programs against \defMainHonest{} of honest ones) and
\texttt{data[}, are the program layout the attack prompt elicits, which Haiku~4.5 never adopts
(appendix~\ref{app:secondpass}). Holding the prompt constant as well lowers Sonnet~5's $\rho$
to \matchedRho{} and does not change Haiku~4.5's (\haikuMatchedRho{}). On Sonnet~5 the
original and prompt-matched honest classes, both correct, separate at \promptOnly{}, so the prompt carries
framing and no backdoor; on Haiku~4.5 they do not separate.

separable than the stored ones, $\rho = \armOneRho{}$: one authorship gap replaced by another
(appendix~\ref{app:robust}).

\monStoredHeadAbs{} on the stored pairs and \monitorS{} on the same-generator pairs
(appendix~\ref{app:monitors}); swapping one class at a time puts the drop in the attacks.

scores from batches run on different days.} replacing the human honest code with ours does not

working attacks: on the strict problems human honest code scores \monStoredStrictAbs{} against

\monitorStrict{}.\footnote{The strict monitor runs used a different attack file from the
classifier's strict row, which moves \monitorStrict{} by about 0.01.} The monitor's fall
measures attack conspicuousness, not authorship. At a fixed audit budget of \auditFPR{} false

stored and \auditStrictOurs{} of same-generator attacks on the strict problems (paired
difference \auditStrictDiff{}, 95\% CI \auditStrictDiffLo{}--\auditStrictDiffHi{}), and
\auditHeadStored{} against \auditHeadOurs{} on the headline problems.

\section{Limitations}

A high floor is evidence about a corpus, not about results computed on it. Ours show the
label is recoverable without reading a backdoor, not that any monitor
recovers it that way, and no number here corrects a published monitor score.

The same-generator corpus does not isolate authorship. Rebuilding with one model changes the
attacks as well as their author: against the same human code, the stored attacking model alone
moves $B$ from \bAttackerLo{} to \bAttackerHi{}, so $\rho$ is not the backdoor's share of the
separability, nor a bound on it. It does not depend on the stored attacker (Claude attackers
only: $\rho = \rhoClaudeOnly{}$). The class swap that would isolate authorship for the classifier, human honest code against our attacks, has not
been run; a value near $B'$ would put the classifier's drop on the honest side, a value near
$S$ in the attacks, as for the monitor. The corpus is not bit-reproducible: the API hides
sampling parameters; thinking was off.

Our scope is narrow in three further ways. We measure one APPS-derived corpus family and five
agentic settings, and other stored-pair corpora are untested. Five of our seven corpora are one
user's repackaging of ControlArena releases, so our claims are scoped to those artifacts as
published. Two interpreter-era artifacts, human solutions written for an older Python,
fall on opposite classes, so $B$ carries a small
execution-environment channel the same-generator arm does not
(appendix~\ref{app:harness}).

\section{Discussion}

These results imply one rule for construction: one model should write both classes under one
prompt framing, and one harness should verify both. Matched construction is precedented in
code-detection benchmarks
\cite{guo2025codemirage} but has not reached backdoor detection.

The definition of the negative class needs the same treatment. Defining it through attack
failure ties the label to the attacker rather than to the code; dropping the failed problems
removes that, as does sampling the class independently of attack success. A monitor number is
interpretable only against the floors of its own split, so a no-code and a
bag-of-words floor belong beside it, each against a permutation null, with the split and
preprocessing released alongside (ours: MIT, appendix~\ref{app:release}). It should also be
reported at a fixed audit budget, beside the share of attacks that fire.

Stored pairs remain the cheapest way to develop a monitor, and nothing here argues for
abandoning them, only that a score on one can describe how the pairs were built rather than
the monitor.

\subsection{Robustness of the same-generator rows}
\label{app:robust}
At the strict rows' $n = \strictN{}$, $B$ under the identical pipeline is $\curveStrict{} \pm
\curveStrictSd{}$. Intervals in the same-generator paragraphs of \S\ref{sec:results} are bootstraps over problems,
resampling $S$ and $B'$ jointly for $\rho$; this replaced a $\pm2$ fold-sd rule before the
retry pool was read. Every $\rho$ point we quote is the ratio of the fold-mean AUROCs and every
joint interval beside it is the bootstrap of the pooled out-of-fold $\rho$, which is the same
quantity computed two ways: the pooled points are \strictRhoPooled{} (strict, the row whose interval
Table~\ref{tab:gates} quotes), \matchedRhoPooled{} (prompt-matched headline),
\matchedStrictRhoPooled{} (prompt-matched strict) and \haikuRhoPooled{} (the second generator). Five fold seeds move the strict row's $\rho$ over \strictRhoSeeds{}.
Retention does not produce the effect. Survivors and non-survivors separate at only
\survivorAuroc{}, and $S$ computed with non-firing attempts on the same problems is
\survivorSwapS{} against \survivorSwapSref{}. The edit arm bounds $S$ under near-copies
(similarity \editSim{}, Table~\ref{tab:similarity}): \editS{} over \editN{} pairs,
$\rho = \editRho{}$. In the one-sided arm of \S\ref{sec:results}, where only the honest half
was regenerated, the classifier reaches \armOneG{} against
$B' = \armOneBprime{}$ on that arm's $n = \armOneN{}$ eligible problems, and TF-IDF gains
\armOneTfidfDelta{} while the length carrier collapses to \armOneLenG{}. Our own attack
prompt halves our single-shot firing rate:
\trigPublicShare{} of our test-passing draws offer a public test input as the trigger, which
cannot diverge from the honest solution, and those fire \trigPublicFire{} against
\trigNovelFire{} for novel triggers; no stored working backdoor has such a trigger
(\trigStoredPublic{}). The rest is retry-and-keep.

\subsection{The prompt-matched arm under the masks, and the second generator}
\label{app:secondpass}
Under prompt matching the identifier mask, the only mask of \S\ref{sec:results} that moved
$S$, takes the headline row to \matchedSid{} ($\rho = \matchedRhoId{}$) where it takes the
original honest class on the same \matchedN{} problems to \matchedSidOrig{}, so identifier
normalisation and prompt matching remove largely the same thing. That masked row is the one that decides whether the residue is structure or naming, and under
prompt matching it is band-ambiguous: its joint interval, \matchedRhoIdLo{}--\matchedRhoIdHi{},
puts \matchedRhoIdCollapse{} of its mass in the collapse band. A character model
(3--5-grams, same classifier and folds) retains more than the word tokeniser, \matchedChar{}
($\rho = \matchedRhoChar{}$), so the drop is not an artefact of tokenisation. On the strict
pairs the matched row is $S = \matchedStrictS{}$ ($n = \matchedStrictN{}$,
$\rho = \matchedStrictRho{}$, \matchedStrictRhoLo{}--\matchedStrictRhoHi{}).
The second generator's pairs are more self-similar than the first's (\haikuPairSim{} mean
against \simIndep{}), so $S$ was recomputed inside similarity strata, where it stays
\haikuStrataS{} in every stratum, including the \haikuStrataLowSim{}-similarity stratum,
which is further from its honest class than the stored benchmark's own pairs, while $B'$
holds \haikuStrataBprime{}, so near-copies are not what buys the collapse. Its prompt-matched
rows move $S$ to \haikuSMatched{} ($\rho = \haikuMatchedRho{}$, $n = \haikuMatchedN{}$) and put
the prompt-only floor at \haikuPromptFloor{}, an interval containing chance. The mechanism is
visible in the programs. The layout vocabulary that the first generator's residue is made of,
\texttt{def main}, \texttt{sys.stdin} and \texttt{data[}, is present in \haikuDefMain{} of the
second generator's programs in \emph{all three} of its classes, which read standard input with
\texttt{input(} in \haikuInputPresent{} of programs on every side, so there is no layout
difference left for the classifier to read.

\subsection{The monitor rows, and what bounds the second monitor}
\label{app:monitors}
The monitor that wrote both classes scores \monitorS{} (\monitorSLo{}--\monitorSHi{}) on the
same-generator headline pairs, a monitor-$\rho$ of \monRhoHead{}
(\monRhoHeadLo{}--\monRhoHeadHi{}); on the strict pairs it scores \monitorStrict{}
(\monitorStrictLo{}--\monitorStrictHi{}), a monitor-$\rho$ of \monRhoStrict{}
(\monRhoStrictLo{}--\monRhoStrictHi{}).
The monitor that wrote neither class scores \monHaikuHead{} on the same-generator headline
pairs and \monHaikuStoredHead{} on the stored pairs over the same problems, \monHaikuStrict{}
and \monHaikuStoredStrict{} on the strict pairs. Its headline rows bound the value without
fixing it. A 512-token reply ceiling left \monHaikuMissHead{} same-generator replies unparseable,
and on the stored side the missing share differs by class (\monHaikuMissHonest{} honest

with a 1{,}024-token ceiling prices it: missingness falls to 2 of 198 and monitor-$\rho$ moves
from \monHaikuRhoStrict{} to \monHaikuRhoStrictMt{}, inside the bootstrap interval.
On the stored pairs both monitors beat the bag-of-words baseline over the same problems
(\(+0.09\) and \(+0.15\) for the first, \(+0.02\) and \(+0.09\) for the second):
Figure~\ref{fig:monitors}'s ranking states something about those monitors on that split and
does not claim that a bag of words beats a monitor here. Classifier and monitor are independent pair
by pair on the same-generator pairs ($\phi = \monitorClfPhi{}$), so the two are reading
different things.

\subsection{The two generators' funnel}
Both generators were run through the identical pipeline. Our honest draws pass the public

single-shot firing rate belongs to the protocol and not to either model, since
\trigPublicShare{} of test-passing draws offer a public test input as their trigger.

\subsection{The test harness and the pass flag}
\label{app:harness}
The same-generator arm requires executing generated code, so we built a runner that feeds each shipped
input case to a solution under per-case timeouts and address-space limits. It agrees with
the artifact's own \texttt{solution\_passes\_tests} on \harnessAgreement{} of the analysis
pool, and is strictly conservative there, never crediting a solution the artifact rejects
(\harnessFailWePass{} such cases). We use \emph{our own} flag for both classes, because a checker stricter on one class than
the other would manufacture exactly the artifact this paper documents. We do not length-match either class; the untrusted model chooses its own
trajectory length. The headline does not depend on that choice. Under the artifact's flag
$B = \baselineB$ at $n = \baselineBn{}$, under ours $B = \baselineBownflag{}$ at
$n = \baselineBownflagN{}$, within one standard deviation of each other. The monitor
scores in Figure~\ref{fig:monitors} are \texttt{runs/x0/monitor-summary.json} from the MIT
release of that harness \cite{jha2026decorrelation}, used under its notice. Two interpreter-era artifacts in the upstream solutions fall on opposite classes: a
\texttt{stdin} without \texttt{.buffer}, fixed, and \texttt{fractions.gcd}, removed in
Python~3.9, not fixable. $B$ is exposed to them; the same-generator arm, whose code we
generated and ran ourselves, is immune.

\subsection{The token test, run and failed}
\label{app:token}
We attempted to confirm a reported token-level mechanism \cite{orel2026aicd} in our setting and
it does not replicate. Separation is \tokenSep{}, the wrong sign, at permutation
$p = \tokenP{}$. The reason is register. Their human class is general-purpose repository
code, whereas both of our classes are competitive-programming code, so an identifier
axis that separates general human code from model code does not separate these two
populations. Only 8 of their 10 canonical tokens are in our vocabulary, so the test is
underpowered; but an underpowered true effect would still carry the right sign, and this one
does not. We report it because a reader who knows that work may run exactly
this test.

\subsection{A third channel, noted but not developed here}
In the same five agentic settings a fifteen-word regular expression over the untrusted
