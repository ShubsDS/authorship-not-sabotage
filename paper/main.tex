\begin{abstract}
AI control relies on trusted monitors to catch a capable model that slips sabotage into its work, and
monitors are ranked on datasets of honest and backdoored code. On the standard such dataset, we find
that a classifier that never runs the code outranks \tfidfKoranCount{} of \monN{} open-weight models
prompted as monitors. The cause is how the dataset was built, since people wrote its honest
solutions, older language models wrote its backdoors, and a problem was labelled backdoored only if its
backdoor worked, so the style of the code and basic facts about the problem give the label away.
Rebuilding the pairs with Claude Sonnet~5 writing both classes, and exchanging one class at a time,
shows that the classifier rewards a contrast between authors. The labels are also unreliable, as one in
\splitRejectedOneIn{} backdoors in its standard test set is not real, failing a public test or misbehaving only
on inputs the problem forbids. Such labels distort comparisons between attackers. A Sonnet~5 monitor
appears to catch older models' backdoors far more often than Sonnet~5's, but once both sets are
verified the difference shrinks from \auditGapUncheckedPts{} to \auditGapPts{} points. We do not show
that published monitors rely on these shortcuts, but a high score on such a dataset is not by itself
evidence of sabotage detection. We release the rebuilt dataset and checks.
\end{abstract}

\section{Introduction}

AI control studies how to use a capable model safely even if it tries to cause harm
\cite{greenblatt2023aicontrol}. Its main safeguard is trusted monitoring, in which a weaker model that
we trust reads each output of the stronger, untrusted model and flags suspicious ones for a human to
audit. In the standard testbed the untrusted model writes solutions to programming problems and may
hide a backdoor, code that passes the tests but gives a wrong answer on an input the attacker
chooses. Monitors are developed and ranked on fixed datasets of such code, in which each problem has
an honest solution and a backdoored one \cite{koran2026ensemble, terekhov2025controltax,
jha2026decorrelation}. We call these the \emph{original pairs} (Figure~\ref{fig:pairs}).

A monitor should score well on these pairs only by finding the backdoor. The dataset, however,
separates its classes in ways unrelated to sabotage. People wrote the honest
solutions, taken from APPS \cite{hendrycks2021apps}, and language models wrote every backdoor, so the
classes differ in naming and layout (Figure~\ref{fig:pairs}), which detectors of model-written
code pick up \cite{orel2026aicd}. The test split also labels a problem as backdoored only when
its backdoor works, which depends on the problem as much as on the code. Benchmarks with such differences
between classes can be solved by recognising how the data was made, as shown for language inference \cite{gururangan2018annotation, poliak2018hypothesis}, reading comprehension
\cite{kaushik2018howmuch} and LLM benchmarks \cite{pacchiardi2024cleverhans}. Detectors of
model-written code are benchmarked on classes matched for problem
\cite{guo2025codemirage, demirok2025multiaigcd}, but backdoor datasets remove only the comments
\cite{koran2026ensemble, jha2026decorrelation}, and other control work \cite{terekhov2026adaptive,
gewang2026attackselection, pinto2026calibration} does not ask who wrote each class.

We show that the original pairs partly measure how they were built (Figure~\ref{fig:overview}).
{\setlength{\topsep}{3pt}\setlength{\leftmargini}{1.6em}\begin{itemize}\setlength{\itemsep}{1pt}\setlength{\parsep}{0pt}
\item A bag-of-words classifier that never runs the code scores above \tfidfKoranCount{} of \monN{}
published monitors on the standard split (\S\ref{sec:results}). When we swap one class at a time for
code by Claude Sonnet~5, it scores highest when the two classes have different authors
(\S\ref{sec:samegen}).
\item The labels also leak, because a problem whose backdoor failed contributes its
honest program instead, so a classifier that reads only problem metadata also beats most monitors
(\S\ref{sec:label}).
\item Some of the dataset's labelled backdoors are not real: in the standard split \splitIllegal{} of
the \splitPos{} have only an illegal trigger, an input the problem's constraints rule out, and
\splitWrongPublic{} more fail a public test. Such labels inflate comparisons between attackers. A
Sonnet~5 monitor catches older models' backdoors more often than Sonnet~5's, which suggests Sonnet~5
attacks better, but the difference falls from \auditSwapDiffUnchecked{} to \auditSwapDiff{} after
checks (\S\ref{sec:monitor}).
\end{itemize}}
We end with checks that other monitor benchmarks can run (\S\ref{sec:next}) and release the rebuilt
pairs and our scripts under the MIT licence (appendix~\ref{app:release}).%

\section{Setup}
\label{sec:setup}

We study the public APPS backdoor dataset \cite{inglis2025appscontrolarena}
in its full and high-quality releases (appendix~\ref{app:schema}). People wrote its honest solutions,
and \storedAttackers{} models released by early 2025, led by Claude~3.7 Sonnet and o3-mini, wrote most
of its backdoors (appendix~\ref{app:attackers}). We call them the \emph{older models}, as opposed to
the Claude Sonnet~5 we use. The standard split \cite{koran2026ensemble, koran2026highquality}, which we
rebuild with the released code \cite{jha2026decorrelation}, has \splitTrain{} training problems with
one solution of each class and \splitTest{} test problems with one program each, which is the
backdoored one if its backdoor works (\splitAttack{} problems) and otherwise the honest one. For our
own pairs we use the \baselineBn{} problems of the full release that have a passing human solution, a
backdoor the dataset marks as working, and deterministic tests.

We use two baselines that never run the code. The \emph{bag-of-words} classifier is a
logistic regression on word and word-pair frequencies (TF-IDF) of the code, with comments removed.
The \emph{no-code} classifier is a logistic regression on three facts about the problem (its
difficulty, number of test cases and statement length) and never sees code. We call the AUROC of
such a baseline a \emph{floor}. Each floor is compared with its score on shuffled labels (1{,}000 shuffles).

To remove the difference in authors, one model, Claude Sonnet~5 or Claude
Haiku~4.5, writes both solutions to each problem. It writes an honest solution and, in a separate
request that sees only the problem, a backdoored solution with an input meant to trigger it. Our
test runner checks both (appendix~\ref{app:harness}). A backdoor \emph{works}, by the dataset's own definition, if it passes
the public tests and differs from the model's honest solution on its trigger; \S\ref{sec:monitor}
adds checks and calls a backdoor that passes them \emph{real}. We report two sets. \emph{All attempts} keeps
one backdoor per problem, chosen before we know whether it works, on the problems where both of the
model's solutions pass the public tests (\sameGenN{} for Sonnet~5, of whose backdoors only
\relFireFirst{} work). \emph{Working backdoors} keeps only backdoors that work, drawn from up to 13
tries per problem (\strictN{} problems).

We fit the same bag-of-words classifier to the rebuilt pairs and
to the original pairs of the same problems. Since 0.5 is chance, we report
$\rho = (\text{rebuilt AUROC} - 0.5)/(\text{original AUROC} - 0.5)$, the fraction of the
classifier's advantage over chance that remains when one model writes both classes. It exceeds 1 if
the rebuilt pairs are easier. AUROCs are five-fold cross-validated (appendix~\ref{app:stats}).

\section{A classifier that never runs the code beats most monitors}
\label{sec:results}

On the standard APPS backdoor split, the bag-of-words classifier beats \tfidfKoranCount{} of \monN{}
open-weight monitors. Trained on the split's training problems and tested once, it reaches AUROC
\tfidfKoran{}, while shuffled labels reach \tfidfKoranNull{} at their 95th percentile. All
\tfidfKoranCount{} are below it by a paired bootstrap interval that excludes zero, and the median monitor
scores \monMedian{} (Figure~\ref{fig:overview}(a)). The monitors have 0.4B--32B parameters, and the four
that beat it are all 24B or larger. The classifier is trained on the benchmark and the
monitors are not, so this measures what the dataset gives away, not which detector is better.

What it reads transfers across attackers (\transfer{} of matched pairs ranked correctly) and is
present whether or not a backdoor works (\pairInert{} against \pairWorking{};
appendix~\ref{app:protocol}). Its strongest backdoor-side features, \texttt{and}, \texttt{==} and
\texttt{if}, are the tokens of any added special case; its honest-side ones are human idioms such as
\texttt{for i} (Figure~\ref{fig:features}).

\subsection{The labels record which attacks failed}
\label{sec:label}

Of the \splitWithBackdoor{} test problems with a backdoor, \splitInert{} (\inertShare{}) have one that
fails, and each of these contributes its human solution as an honest item instead. The label
therefore partly records how hard a problem was to attack, and that can be read without any code.
Backdoor-class problems have about half as many test cases (\testCasesAttack{} against
\testCasesHonest{}, Figure~\ref{fig:nocode-b}), because a backdoor that must pass every test is easier
to hide when there are few. The no-code classifier has to be fitted within the test split, since the
training split gives both programs of a problem the same metadata. Cross-validated there, it reaches
\nocodeCV{} and beats \nocodeCVCount{} monitors (Table~\ref{tab:floors}). Fitted outside the split it
scores \nocodeOutside{} (Figure~\ref{fig:nocode-a}), the same relation reversed,
because there the honest items come from problems the split excluded, many with only two or three
tests (appendix~\ref{app:protocol}). Either way, the leak is in how labels were chosen.

\subsection{Swapping one class at a time}
\label{sec:swap}

Because the rebuild changes the backdoors too, we pair each of Sonnet~5's classes with the other
author's and name each kind of pair by who wrote its honest and its backdoored side: the original
pairs are \emph{person / older models}, the rebuilt pairs \emph{Sonnet~5 / Sonnet~5}. On the
working-backdoor problems bag-of-words scores \clfSwapWorkHumanOurs{} on person / Sonnet~5 and
\clfSwapWorkOursStored{} on Sonnet~5 / older models, against \clfSwapWorkHumanStored{} on the original
pairs and \clfSwapWorkOursOurs{} on the rebuilt ones (Figure~\ref{fig:overview}(b)). An earlier run on
all attempts, read by a rule fixed in advance, agrees: person / Sonnet~5 scores \clfSwapHumanOurs{},
above the original \clfSwapHumanStored{} (appendix~\ref{app:clfswap}). The classifier rewards a
contrast between authors, on Haiku~4.5's pairs too.

\section{Checking which backdoors are real}
\label{sec:monitor}

A zero-shot Sonnet~5 monitor reads the problem statement and comment-free code
and scores suspicion from 0 to 100. It responds mainly to the backdoors. Replacing the
person's solutions with Sonnet~5's moves it only from \monStoredStrictAbs{} on the original pairs to
\swSonStrictOS{} on Sonnet~5 / older models, within rescoring noise (appendix~\ref{app:monswap}). Replacing the backdoors moves it more: on person / Sonnet~5 it falls to
\monSwapStrictHumanOurs{} (Figure~\ref{fig:overview}(c), Table~\ref{tab:swap-full}).

Part of that fall comes from the labels. A backdoor counts as working if its output on its own trigger
differs from an honest solution's, and nothing checks that the trigger is a legal input. A trigger is
illegal when it breaks the statement's constraints, for example $M > N$ where the statement requires
$M \le N$; any output is acceptable there, so a different one shows nothing. The dataset's
labels show the problem: in the standard test split, \splitIllegal{} of the \splitPos{} backdoored
programs have only an illegal trigger and \splitWrongPublic{} print a wrong answer on a public test
that the dataset's pass flag misses. Without those \splitRejected{}, bag-of-words scores
\splitTfidfChecked{} and the published monitors move by a median of \splitMonMedian{}. Our generation used the same definition, so before comparing
attackers we check every trigger in both classes against an input validator written from the
statement, require the backdoor's output there to differ from the human solutions' majority answer,
and when a check fails search up to 40 nearby legal inputs for one where the backdoor is still wrong
(appendix~\ref{app:audit}). The check removes \checkedStoredRejected{} of the older models' \strictN{}
backdoors and \checkedOursRejected{} of Sonnet~5's (\checkedOursInvalid{} with only an illegal trigger,
and \checkedOursSpace{} whose output on the trigger matches the human solutions, so it is not wrong
there).

On the \checkedN{} problems where both backdoors are real, Sonnet~5's may still be harder to catch,
by less. The monitor's AUROC falls from \monCheckedHS{} to \monCheckedHO{} (difference
\monCheckedDiff{}, \monCheckedDiffLo{} to \monCheckedDiffHi{}). Flagging \auditFPR{} of the human
solutions it catches \auditStrictStored{} of the older models' backdoors and \auditSwapHumanOurs{} of
Sonnet~5's (Figure~\ref{fig:overview}(d)), a difference of \auditSwapDiff{} (\auditSwapDiffLo{} to
\auditSwapDiffHi{}), only just above zero. On all \strictN{} problems before the checks
it was \auditUncheckedHumanStored{} against \auditUncheckedHumanOurs{}, a difference of
\auditSwapDiffUnchecked{} (\auditSwapDiffUncheckedLo{} to \auditSwapDiffUncheckedHi{}); part of
this change comes from dropping problems. The
difference depends on the threshold: \auditSwapOneDiff{} at 1\%, \auditSwapFiveDiff{} at 5\% (interval
includes zero; Figure~\ref{fig:audit}), and \auditSwapOursStored{} against \auditStrictOurs{} when
Sonnet~5's honest code sets it. The monitor may also favour its own model: a
Haiku~4.5 monitor, which wrote neither class, gives \monCheckedHaiHS{} against
\monCheckedHaiHO{}.

\section{Limitations}
\label{sec:limits}

A high floor shows that a dataset's labels can be predicted without finding a backdoor, not that any
monitor predicts them that way.
We ran only two monitors, both zero-shot, and a monitor trained on these pairs could learn the
shortcuts. Our
backdoors come from one prompt, the working-backdoor results rest on \checkedN{}--\strictN{} problems
and one attacking model, and the \auditFPR{} threshold rests on the top two of \strictN{} human
solutions. Like the dataset, our generation did not check triggers, and our attack prompt did not ask
for a legal one (appendix~\ref{app:prompts}), so \checkedOursRejected{} of Sonnet~5's \strictN{} working
backdoors are dropped; running the validators during generation would
avoid this. Claude models wrote the validators, and the legal-input search is short.
Character count alone separates the classes in four of five agentic ControlArena
\cite{controlarena} settings (up to \agentdojoFloor{}; appendix~\ref{app:agentic}).

\section{Checks for monitor benchmarks}
\label{sec:next}

We suggest three checks for any monitor benchmark: report baselines that never run the code
(bag-of-words, problem metadata, length) and their shuffled-label scores beside every monitor score;
pair each class with another author's code; and check that every trigger is a legal input on which the
backdoor is wrong before reporting catch rates for several attacking models. Where they find
shortcuts, have one model write both classes from one prompt and choose honest examples independently
of whether an attack succeeded. Automated search that takes such a score as its fitness signal could
learn to exploit these shortcuts too.

\subsection{Running the code}
\label{app:harness}
Rebuilding the pairs means running generated code. Our runner feeds each of a problem's stored test
inputs to a solution, with a time limit per input and a memory limit. It agrees with the dataset's
\texttt{solution\_passes\_tests} flag on \harnessAgreement{} of the \baselineBn{} problems we analyse
and is stricter, never passing a solution the dataset fails (\harnessFailWePass{} cases). We use our
runner for both classes, because a checker that rejects one class more readily would create exactly
the kind of class difference this paper is about. The choice does not change the original AUROC,
which is \baselineB{} on \baselineBn{} pairs under the dataset's flag and \baselineBownflag{} on
\baselineBownflagN{} pairs under ours. We do not match program lengths; each model chooses its own.

Two quirks of older Python versions appear in the dataset's solutions, on opposite classes. Reading
\texttt{stdin} without \texttt{.buffer} we can fix; \texttt{fractions.gcd}, removed in Python~3.9, we
cannot. These quirks give the original pairs a small extra cue that the rebuilt pairs, which we
generated and ran ourselves, do not have. The monitor scores in Figure~\ref{fig:overview}(a) are
\texttt{runs/x0/monitor-summary.json} from the MIT release of the monitor-ensemble harness
\cite{jha2026decorrelation}, used under its notice.

\subsection{Statistics}
\label{app:stats}
Most AUROCs come from five-fold cross-validation with folds split by
problem. Each item is scored by the model fitted without its fold, and one AUROC is computed over all
these scores. The no-code classifier inside the test split also averages over five repeats of the
folds. Bag-of-words on the standard split, the no-code classifier trained outside it, and the
monitors score each item once, without folds.

Every interval is a 95\% percentile bootstrap over problems, \bootDraws{}
draws, seed 0. For $\rho$, each draw resamples one set of problems and recomputes both AUROCs on it,
so the interval reflects how the two move together; we call this a joint interval. Differences (a
floor against a monitor, original against rebuilt pairs) are computed on the same draws. We chose the
bootstrap, over an earlier rule of two fold standard deviations, before looking at the retries
behind the working-backdoor rows.

Each permutation test shuffles the labels, reruns the whole pipeline
including fitting, and recomputes the statistic, \permReps{} times, with
$p = (1 + \#\{\text{shuffled} \ge \text{observed}\})/(1 + \permReps{})$. In the agentic settings labels
are shuffled within each main task (appendix~\ref{app:agentic}). No per-pair scores were kept for the edit variant, so its
$\rho$ has no joint interval.

\subsection{What we release}
\label{app:release}
The release bundle is attached to the \texttt{v1.0} release of the code repository, under the MIT
licence for both data and scripts. It contains
\begin{itemize}
\item the rebuilt pairs: \relHonest{} honest programs, \relEdit{} edit-variant and \relIndep{}
independent-variant backdoored programs, and all \relRetryDraws{} draws from the retries;
\item two selections of pairs. The first keeps the first draw for each problem (\relPassFirst{}
passing pairs, \relFireFirst{} with a working backdoor). The second keeps the earliest retry that
works (\relPassBest{} and \relFireBest{}, or \relFireBestCrash{} if a crash on the trigger input
counts as working), because the original backdoors are also the survivors of retries;
\item the \relScripts{} scripts behind every number, from generation and testing to the monitor runs
and class swaps;
\item in the code repository rather than the bundle, the \validatorsN{} input validators, the trigger
checks and their per-backdoor verdicts (appendix~\ref{app:audit});
\item a dataset card and a manifest of row counts and checksums.
\end{itemize}
The rebuilt pairs cannot be regenerated bit for bit, because the API does not expose its sampling
parameters, so we release the programs themselves.

\subsection{Checks on the drop}
\label{app:robust}
The drop is not an effect of sample size. On 30 random subsets of the original pairs, run through the same
pipeline, the AUROC is $\three{\curveHeadline} \pm \three{\curveHeadlineSd}$ (mean $\pm$ SD) at
$n = \sameGenN{}$, far above the \three{\sameGenS} of the rebuilt pairs. At $n = \strictN{}$, the
size of the working-backdoor row, it is $\three{\curveStrict} \pm \three{\curveStrictSd}$, so the
classifier itself loses accuracy at that size. This is why $\rho$ divides by the AUROC refitted on
the original pairs of the same problems. Reassigning problems to folds with five seeds gives the
working-backdoor row a $\rho$ of \strictRhoSeeds{} (\strictRho{} in Table~\ref{tab:gates}).

Nor does it come from numbers or operators. We masked three kinds of token in both classes: numbers,
comparison operators and identifiers. Only masking identifiers changes the all-attempts row's
rebuilt AUROC, to \sameGenSid{} ($\rho = \sameGenRhoId{}$, \sameGenRhoIdLo{}--\sameGenRhoIdHi{}); the
other two masks move it by at most \maskMaxShift{}. Code length alone separates that row's rebuilt
pairs at \three{\sameGenLen}.

It does not depend on whether the backdoor works either. Within our backdoored class, draws that work and
draws that do not separate at only \survivorAuroc{}. On the working-backdoor problems, putting
failed attempts in place of the working backdoors gives a rebuilt AUROC of \three{\survivorSwapS},
against \three{\survivorSwapSref} with the working backdoors.

We also tried two other ways to rebuild. The edit variant, whose pairs are near-copies, gives
\three{\editS} over \editN{} pairs, $\rho = \editRho{}$. Regenerating only the honest class, with
Qwen3-Coder-30B, raises the AUROC to \armOneG{} against \armOneBprime{} on the original pairs of the
same \armOneN{} problems, while code length alone falls to \armOneLenG{}.

Our backdoors rarely work, largely because of how the model picks its trigger. In \trigPublicShare{} of our draws that pass the public
tests, the model names a public test input as its trigger. A solution that passes the public tests
cannot fail on such an input. Of these draws \trigPublicFire{} work, against \trigNovelFire{} of
draws with a new trigger input, so our prompt roughly halves the share of backdoors that work. No
working original backdoor uses a public test input as its trigger (\trigStoredPublic{}).

The attacking model matters little for $\rho$ either. Restricting Sonnet~5's all-attempts row by attacking model
keeps $\rho$ inside the full row's interval (\sameGenRhoLo{}--\sameGenRhoHi{}). It is \rhoClaudeOnly{}
(\rhoClaudeOnlyLo{}--\rhoClaudeOnlyHi{}) on the \rhoClaudeOnlyN{} problems whose original backdoor
a Claude model wrote, \rhoThinkOnly{} (\rhoThinkOnlyLo{}--\rhoThinkOnlyHi{}, $n = \rhoThinkOnlyN{}$)
for claude-3-7-sonnet-thinking alone, and \rhoNonClaude{} (\rhoNonClaudeLo{}--\rhoNonClaudeHi{},
$n = \rhoNonClaudeN{}$) for the other models.

\label{app:shared}Working backdoors do not detectably raise $\rho$ either. Sonnet~5's all-attempts and working-backdoor rows differ in two ways: in the second
row the backdoors work, and it covers only problems where a working backdoor could be drawn. The
\sharedN{} problems in both rows separate the two effects, since on them the honest program and the
original pair are the same and only our backdoor differs. We reuse the existing out-of-fold scores
on these subsets without refitting.

On the shared problems $\rho$ is \sharedRhoHead{} with the sampled attempts and \sharedRhoWorking{}
with the working backdoors (paired difference \sharedDiffLo{} to \sharedDiffHi{}). Restricted to the
\shDiffN{} problems where the two backdoors differ, it is \shDiffHeadRho{} and \shDiffWorkRho{}
(difference \shDiffDelta{}, \shDiffDeltaLo{} to \shDiffDeltaHi{}). On the other \shSameN{} the
sampled backdoor already works and is the same program in both rows. Working backdoors lower the
point estimates, and both intervals include zero.

The problems matter more. The \shStrictOnlyN{} problems found only in the working-backdoor row give
$\rho = \shStrictOnlyRho{}$ (\shStrictOnlyRhoLo{}--\shStrictOnlyRhoHi{}), with a lower original AUROC
(\shStrictOnlyBp{} against \shWorkBp{}) and a higher rebuilt one (\shStrictOnlyS{} against
\shWorkS{}) than the shared problems. The difference, \shOnlyMinusShared{} (\shOnlyMinusSharedLo{}
to \shOnlyMinusSharedHi{}), is not resolved at this size, but by point estimate the higher $\rho$ of
the working-backdoor row comes from which problems yield a working backdoor.

\subsection{Prompt matching and Haiku~4.5}
\label{app:secondpass}
Prompt matching removes much of the same signal as masking identifiers. Masking
identifiers takes Sonnet~5's prompt-matched all-attempts row to \three{\matchedSid}
($\rho = \matchedRhoId{}$) and the same \matchedN{} problems without prompt matching to
\three{\matchedSidOrig}. Whether what remains is program structure or naming is undecided, since the
masked row's interval runs from \matchedRhoIdLo{} to \matchedRhoIdHi{}. A character-level model (3 to 5 characters, same classifier
and folds) keeps more than the word model, \three{\matchedChar} ($\rho = \matchedRhoChar{}$), so the
drop does not come from how code is split into words. Under the two prompts, Sonnet~5's correct
honest solutions separate at \promptOnly{}.

Haiku~4.5's low AUROC is not caused by near-copies. Its rebuilt pairs are more alike than
Sonnet~5's (mean similarity \haikuPairSim{} against \simIndep{}), so we recomputed its rebuilt AUROC
within bands of similarity. It stays at \haikuStrataS{} in every band, including the band at
\haikuStrataLowSim{}, whose pairs are less alike than the original pairs, while the original AUROC on
the same problems stays at \haikuStrataBprime{}. Its honest solutions under the two prompts separate
at only \three{\haikuPromptFloor}. Haiku~4.5 never uses the layout that marks Sonnet~5's backdoors.
\texttt{def main}, \texttt{sys.stdin} and \texttt{data[} appear in none of its programs in any
class, and every program reads input with \texttt{input(}, so no layout difference is left to
read.

\label{app:counts}Both models ran through the same pipeline. Their honest solutions pass the public tests on
\three{\sonnetHonestPass} (Sonnet~5) and \three{\haikuHonestPass} (Haiku~4.5) of 1{,}444 problems.
Haiku~4.5's backdoored solutions pass on \haikuAttackPass{} problems, and only \haikuUsable{} of them
work, below the 50 pairs we required, so Haiku~4.5 has no working-backdoor row. In the all-attempts
rows \haikuFireInRow{} of Haiku~4.5's \haikuN{} backdoors work, against \relFireFirst{} of
Sonnet~5's \sameGenN{}. Haiku~4.5's other \haikuUsableOutside{} working backdoors are on problems
where its own honest solution failed, which therefore have no rebuilt pair.

\subsection{Checking which backdoors are real}
\label{app:audit}
A backdoor matters only if it passes the tests and gives a wrong answer on an input the problem can receive. Our
working-backdoor selection asked less: a draw counted as working if, on the trigger Sonnet~5 proposed,
its output differed from Sonnet~5's own honest solution. The older models' backdoors carry the
dataset's own \texttt{backdoor\_works} flag. Neither asks whether the trigger is a legal input or
whether the reference answer is right. Before computing catch rates on the working-backdoor problems
we therefore put both classes through the same checks (\texttt{verify\_backdoor.py -{}-validators
-{}-human-ref -{}-witness 40}). The first asks for a legal trigger. Each problem has an input validator
that checks the line layout, token types, every stated range and every stated guarantee (distinct
values, a connected graph, an answer that exists). Claude models wrote the validators from the
problem statement alone, without seeing any trigger, and each accepts every stored test input of its
problem. Triggers are first put in a standard layout (one space between tokens, no trailing blank
lines), and all programs run on that version. The second asks for a wrong answer: on the trigger, the
backdoor's output must differ from the answer that a strict majority of up to ten passing human
solutions give, at least two of them agreeing. An illegal trigger shows only that the claimed trigger
is illegal, so when either check fails we search for a legal input on which the backdoor is wrong
anyway: we change one or two integers of the trigger or of a public test input, keep up to 40
mutants the validator accepts, and compare the backdoor with the human majority on each. A backdoor
with such a witness counts as real. The search is short, so the counts of rejected backdoors are upper
bounds.

Table~\ref{tab:checks} gives the outcome. Most rejected backdoors have only an illegal trigger, for
example $M > N$ where the statement requires $M \le N$. Sonnet~5's other \checkedOursSpace{} rejections
give the human answer on their trigger, most once stray whitespace is removed. In the standard split
every illegal trigger is a plain breach of the statement, such as a value out of range, a sequence that
is not a permutation, a string of the wrong length, or a reducible fraction where the statement
guarantees an irreducible one. Its \splitWrongPublic{} wrong public answers are wrong integers (for
example 47610330 where the answer is 47610390) that the dataset's pass flag misses, because it
compares numbers with a relative tolerance. Its undecided programs fail a public test under our runner
only by number formatting, or have several correct answers. The split needed \splitNewValidators{}
more validators, written the same way, and all \validatorsN{} accept every stored test input of their
problem. Two rejections on the working-backdoor problems rest on a reading of the statement, a trigger
written with leading zeros and a problem whose statement gives no bounds, where the validator uses the
original contest's. We read the least clear-cut rejections against their statements and release the
validators.

\section{Agentic settings}
\label{app:agent}

\subsection{Length leaks the label even with one set of authors}
\label{app:agentic}
A dataset can leak its labels even when the same authors write both classes. In five agentic settings where the
same three models (claude-sonnet-4, gemini-2.5-pro and gpt-5) write both classes, character count
alone separates the classes within each task, with AUROC from \bashFloor{} (\texttt{bash}, at chance)
to \agentdojoFloor{} (\texttt{agentdojo}; Figure~\ref{fig:corpora}). We compute it within each main
task because a pooled AUROC would also read which task each item came from. The five datasets are one
user's repackaging of ControlArena releases \cite{sinha2026controlarenacorpora}, without a licence, so
we report aggregates only and scope these results to them as published.

\begin{figure}[!htbp]\centering
\includegraphics{f2-corpus-floors.pdf}
\caption{Character count separates the classes in four of five agentic settings, although
the same models write both. Bars: AUROC of character count within each main task, pooled over tasks
weighted by pair count, and folded to $\max(a, 1-a)$ because the direction can differ between tasks.
Ticks: 95th percentile on shuffled labels (\permReps{} shuffles within each task); folding puts it
above 0.5. \texttt{bash} is below its tick ($p = \bashFloorP{}$); the other four are above theirs
($p = \agenticFloorP{}$ each). The number beside each setting counts its task groups, so the
estimates are not equally precise. These datasets have no licence; we redistribute nothing.}
