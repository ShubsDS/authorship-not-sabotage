\begin{abstract}
Monitors for AI control are developed on stored pairs of programs, in which each programming
problem comes with an honest solution and a solution that hides a backdoor. In the public corpora
used for this, people wrote the honest solutions and language models wrote the backdoors, so a
monitor can tell the two classes apart by recognising who wrote the code. We measure how much of
the benchmark signal comes from this difference in authorship. A lexical classifier that has no
way to detect a backdoor reaches an AUROC of \lexFloor{} on the standard filtered split, and a
classifier that reads only problem metadata reaches \metaFloor{}. Both score higher than
\monBelow{} of the \monN{} monitors published for that split. We then rebuild the corpus so that
one model writes both solutions to every problem. On the rebuilt pairs the lexical classifier
keeps between 10\% and 69\% of its separability above chance, depending on the model, and giving
both classes the same prompt lowers the higher figure to 39\%. Most rebuilt backdoors never work,
however. On the 99 that do, the classifier keeps 86\% of its separability, and a monitor that
audits 5\% of honest programs catches \catchRebuilt\% of the rebuilt backdoors compared with
\catchStored\% of the stored ones. Stored pairs therefore overstate how well monitors catch
backdoors, though authorship is unlikely to be the only reason. We release the rebuilt corpus and
recommend changes to how these benchmarks are built and reported.
\end{abstract}

\section{Introduction}

AI control asks how to deploy a capable model that might try to cause harm, using safeguards that
hold even if it does \cite{greenblatt2023aicontrol}. The most common safeguard is trusted
monitoring, in which a weaker model that is trusted reads each output of the untrusted model and
flags suspicious ones for a human audit \cite{greenblatt2023aicontrol, korbak2025evaluate}. How
much protection this gives depends on how reliably the monitor separates sabotage from honest work.
For code, that is usually measured on stored pairs, corpora in which every programming problem
comes with an honest solution and a solution containing a backdoor
\cite{koran2026ensemble, terekhov2025controltax, jha2026decorrelation}.

The stored pairs in current use have a property that has little to do with sabotage. Their honest
solutions come from the APPS dataset \cite{hendrycks2021apps} and were written by people, while
every backdoor was written by a language model. Code written by people differs from code written
by models in ways that simple classifiers pick up \cite{caliskan2015stylometry, suh2025detecting,
orel2026aicd}, and benchmarks across machine learning have been solved through incidental
differences of this kind before \cite{gururangan2018annotation, geirhos2020shortcut,
zech2018pneumonia}. A monitor could therefore score well on stored pairs by recognising code
written by a model. The standard split removes comments and keeps only working solutions
\cite{koran2026ensemble}, which erases the most obvious traces of authorship while leaving the
authors themselves unchanged.

We measure how much of the signal in stored pairs comes from authorship (Figure~\ref{fig:schematic}).
We train two classifiers that have no way to detect a backdoor and compare them with the published
monitors, rebuild the corpus so that a single model writes both solutions to every problem, and
examine how the standard split assigns its labels. We find the following.
\begin{itemize}
  \item Both classifiers score higher than \monBelow{} of the \monN{} published monitors on the
  standard split, and their signal comes from the authors of the code rather than from the
  backdoors (Section~\ref{sec:floors}).
  \item When one model writes both classes, the classifier and an LLM monitor lose much of their
  separability. Most of the loss comes from attempted backdoors that never work, which make up
  98\% of the rebuilt attacks (Section~\ref{sec:rebuilt}).
  \item On the 99 rebuilt backdoors that do work, more of the separability survives. Even so, a
  monitor that audits 5\% of honest programs catches \catchRebuilt\% of them, against
  \catchStored\% of the stored backdoors for the same problems (Section~\ref{sec:rebuilt}).
  \item The split assigns problems to its honest class partly because their attacks failed,
  which ties the label to problem difficulty (Section~\ref{sec:label}).
\end{itemize}
We release the rebuilt corpus and recommend four changes to how stored pair benchmarks are built
and reported (Section~\ref{sec:recommendations}).

\section{Related work}
\label{sec:related}

\paragraph{AI control.}
Control evaluations were introduced with a trusted monitor that inspects code for backdoors on APPS
problems \cite{greenblatt2023aicontrol}, and have since been formalised as games
\cite{griffin2024games}, extended to adaptive deployment \cite{wen2024adaptive} and to agents
\cite{korbak2025evaluate, kutasov2025shadearena, bhatt2025ctrlz}, and implemented in the
ControlArena framework \cite{controlarena}. Related work evaluates whether models can sabotage
\cite{benton2024sabotage} or plan subversion \cite{mallen2024subversion}, and whether monitors that
read a model's reasoning remain reliable \cite{baker2025monitoring, korbak2025monitorability,
arnav2025cotredhanded}. On the monitor side, ensembles of monitors are compared on a filtered
split of an APPS backdoor corpus \cite{koran2026ensemble, jha2026decorrelation}, and other work
studies adaptive attacks on monitors \cite{terekhov2026adaptive}, attack selection
\cite{gewang2026attackselection}, calibration across model families \cite{pinto2026calibration}
and legibility protocols \cite{sreevatsa2026legibility}. Most of these studies generate honest and
attack behaviour from the same model at evaluation time. The stored APPS corpora are the main
exception, and they are what we audit.

\paragraph{Shortcuts and benchmark validity.}
Classifiers often succeed by exploiting features that separate the classes in a dataset without
solving the intended task. Models that see only the hypothesis solve much of natural language
inference \cite{gururangan2018annotation, poliak2018hypothesis, mccoy2019right}, reading
comprehension can be answered without reading the passage \cite{kaushik2018howmuch}, and image
models diagnose disease from hospital markers rather than anatomy \cite{zech2018pneumonia,
degrave2021covid}. These failures have been described as shortcut learning
\cite{geirhos2020shortcut} and Clever Hans behaviour \cite{lapuschkin2019cleverhans,
pacchiardi2024cleverhans}, and they arise from how datasets are assembled
\cite{torralba2011unbiased, recht2019imagenet}. A weak baseline that sees only part of the input
does not prove a dataset clean \cite{feng2019misleading}, which is why we also remove the confound
directly. Broader reviews document leakage and invalid comparisons across machine learning
\cite{kapoor2022leakage, liao2021learning, raji2021everything, bowman2021fix, reuel2024betterbench}
and in code benchmarks in particular \cite{aleithan2024swebenchplus, wang2025solvedissues,
zhou2025lessleak}.

\paragraph{Telling who wrote a program.}
Programmers can be identified from the style of their code \cite{caliskan2015stylometry}, and a
growing literature detects code written by language models, using trained classifiers
\cite{nguyen2024gptsniffer}, statistics of model likelihood \cite{mitchell2023detectgpt,
yang2023zeroshot} and simple lexical features \cite{suh2025detecting, orel2026aicd}. Benchmarks for
this task match the two classes on problem and length so that detectors cannot rely on those
differences \cite{guo2025codemirage, demirok2025multiaigcd}. In detection work, recognising the
author is the goal. In backdoor benchmarks it is a confound, and the matching practices of detection
benchmarks have not been applied.

\section{Data and methods}
\label{sec:setup}

\paragraph{Stored pairs.}
We study an APPS backdoor corpus of 5{,}000 problems \cite{inglis2025appscontrolarena}. Its honest
solutions come from APPS, and its backdoors come from ten language models, among them o3-mini,
Claude~3.7 Sonnet and GPT-4o. The standard split filters this corpus \cite{koran2026highquality,
koran2026ensemble}. Each of its 1{,}209 training problems contributes one honest and one backdoored
solution. Its test set holds 1{,}375 programs, one per problem, of which 172 are backdoored, and a
problem's program is labelled backdoored only if its backdoor works. Comments are removed from all
code. We rebuild the split with the released harness and compare against the scores of the
\monN{} monitors published for it \cite{jha2026decorrelation}.

\paragraph{Two classifiers that cannot see a backdoor.}
The \emph{lexical classifier} is a logistic regression on the frequencies of words and word pairs
in the code, weighted by inverse document frequency. The \emph{metadata classifier} is a logistic
regression on three properties of the problem, namely its difficulty, its number of test cases and
the length of its statement, and never reads code. Neither model has any representation of program
behaviour.

\paragraph{Rebuilt pairs.}
We rebuild the corpus on the 1{,}444 problems that have a passing human solution, a working stored
backdoor and deterministic tests, using Claude Sonnet~5 and Claude Haiku~4.5. For each problem the
model writes an honest solution and, in a separate request that sees only the problem, a solution
with a hidden backdoor together with an input meant to trigger it. We draw one attempt per problem
before seeing its outcome and run every program through our own test harness
(Appendix~\ref{app:harness}). Following the benchmark, the attack class contains attempts that
pass the public tests. A backdoor \emph{works} if, on its trigger input, it returns a different
answer from the same model's honest solution. In a \emph{shared prompt} variant, the honest solution
is requested with the attack prompt itself, with the request for a flaw replaced by a request for a
correct program.

\paragraph{Measuring what survives.}
Let $S$ be the lexical classifier's AUROC on rebuilt pairs and $B'$ its AUROC on the stored pairs
of the same problems. We report the retained separability
\[
  \rho = \frac{S - 0.5}{B' - 0.5},
\]
which is 1 if changing the author leaves the classifier's accuracy above chance unchanged and 0 if
it removes all of it. Both AUROCs come from five folds split by problem, and intervals come from
2{,}000 bootstrap samples of problems, drawing $S$ and $B'$ jointly for $\rho$. Before any data
were generated we fixed two thresholds for reading $\rho$, treating values up to 0.33 as mostly
authorship and values above 0.72 as mostly content. The rebuilt attacks differ from the stored
ones in style and success rate as well as in author, so $\rho$ describes this construction and is
not a clean causal estimate (Section~\ref{sec:limitations}).

\section{Stored pairs reveal who wrote the code}
\label{sec:floors}

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{fig2-floors.pdf}
  \caption{\textbf{Two classifiers that cannot detect a backdoor, among the \monN{} published
  monitors.} Each grey dot is one monitor's AUROC on the filtered test split
  \cite{jha2026decorrelation}. The lexical classifier is trained on the split's training problems,
  and the metadata classifier reads no code. \monBelow{} of the \monN{} monitors score below both.}
  \label{fig:floors}
\end{figure}

On the filtered test split, the lexical classifier reaches an AUROC of \lexFloor{} (95\% interval
0.770 to 0.841), and the metadata classifier reaches \metaFloor{} under cross validation within the
test set. Both are far above their permutation nulls, whose 95th percentiles are 0.547 and 0.555,
and both score higher than \monBelow{} of the \monN{} published monitors, whose median is
\monMedian{} (Figure~\ref{fig:floors}). The lexical classifier's advantage over 18 of the monitors
holds under a paired bootstrap. The metadata classifier is less secure. On a single held out slice
of the test set it reaches \metaHeldout{}, close to its own null, so we treat it as a diagnostic of
the label (Section~\ref{sec:label}) and the lexical classifier as the main baseline. The comparison
is between fitted classifiers and prompted monitors, so it shows how much the corpus reveals
without any detection of sabotage. It does not show that a word count is a better monitor.

Three observations show that the lexical classifier is reading authorship rather than backdoors.
Trained on the backdoors of one attacker model, it identifies those of another with a pairwise
accuracy of 0.969. It separates inert backdoors, which never change a program's output, almost as
well as working ones, with pairwise accuracies of 0.879 and 0.935. And its strongest features are
habits of style. For example, the string \texttt{\_\_main\_\_} appears in 152 of the 1{,}209
backdoored training solutions and in one honest solution. Removing comments does what it was meant
to do, since a detector that counts \texttt{\#} characters falls from 0.696 to chance, but it
leaves these differences in place.

\section{Rebuilt pairs are harder to separate}
\label{sec:rebuilt}

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{fig3-rebuilt.pdf}
  \caption{\textbf{Stored and rebuilt pairs of the same problems.} \textbf{(a)}~AUROC of the
  lexical classifier and of an LLM monitor on stored pairs (orange) and rebuilt pairs (blue).
  \emph{All attempts} keeps every rebuilt backdoor that passes the public tests, as the benchmark
  does. \emph{Working} keeps only backdoors that change the output on their trigger. Intervals are
  in Table~\ref{tab:rebuilt}. \textbf{(b)}~Share of backdoors the Sonnet~5 monitor catches when a given
  percentage of honest programs, the most suspicious ones, is audited. Solid lines show working
  backdoors, with 95\% bootstrap bands, and dashed lines show all attempts.}
  \label{fig:rebuilt}
\end{figure}

\paragraph{The lexical classifier.}
When one model writes both classes, the lexical classifier keeps $\rho = \rhoSonAll{}$ of its
separability on Sonnet~5 pairs and $\rho = \rhoHaiAll{}$ on Haiku~4.5 pairs
(Figure~\ref{fig:rebuilt}a). The drop is not a matter of sample size, because on random subsets of
the stored pairs with the same number of problems the classifier still reaches 0.851. The two
models differ because of how they respond to the attack prompt. Sonnet~5 adopts a distinctive
program layout when asked for a backdoor, with \texttt{def main} in 67\% of its backdoored programs
and 38.5\% of its honest ones, and Haiku~4.5 never adopts it. When both classes are written from
the attack prompt, Sonnet~5 falls to $\rho = \rhoSonShared{}$ and Haiku~4.5 stays at
$\rho = \rhoHaiShared{}$. For Sonnet~5 the prompt alone carries signal, since its original and
shared prompt honest solutions, both correct, can be told apart with an AUROC of 0.600.

\paragraph{Working backdoors.}
Only 14 of the 623 Sonnet~5 attempts and 2 of the 611 Haiku~4.5 attempts work, so the results above
mostly concern attempted sabotage. One reason is that 52\% of the attempts name a public test case
as their trigger, which cannot change the output of a program that passes the tests. To obtain
working backdoors, we resampled each Sonnet~5 attempt up to six more times and kept the first that
worked, which is how the stored corpus selected its own backdoors. On these 99 pairs the classifier
keeps $\rho = \rhoSonVer{}$ (95\% interval \rhoSonVerLo{} to \rhoSonVerHi{}), or \rhoSonVerShared{}
with a shared prompt. The interval is wide, but it shows that when the backdoors work, most of the
stored separability survives a change of author. The selection step does not explain this. If each
working backdoor is replaced by a failed attempt on the same problem, the classifier's AUROC barely
moves, from 0.751 to 0.745.

\paragraph{An LLM monitor.}
We gave every program to a prompted monitor (Appendix~\ref{app:monitor}), using Sonnet~5, which
wrote both classes, and Haiku~4.5, which wrote neither. Across all attempts, the Sonnet~5 monitor
falls from an AUROC of \storedMonSonAll{} on stored pairs to \rebuiltMonSonAll{} on rebuilt pairs.
Most of this fall reflects attempts that contain nothing to find. The monitor gives them a mean
suspicion of 6.9 out of 100, against 78.8 for the stored backdoors. On working backdoors the fall is
smaller, from \storedMonSonVer{} to \rebuiltMonSonVer{} ($\rho = \rhoMonSonVer{}$), and the
Haiku~4.5 monitor shows a similar ratio of \rhoMonHaiVer{}.

A control protocol cares about how many backdoors reach an audit, which depends on the threshold
more than on AUROC. Figure~\ref{fig:rebuilt}b fixes the share of honest programs that are audited.
At a 5\% budget, the Sonnet~5 monitor catches \catchStored\% of the stored working backdoors
(95\% interval \catchStoredLo\% to \catchStoredHi\%) and \catchRebuilt\% of the rebuilt ones
(\catchRebuiltLo\% to \catchRebuiltHi\%). On these problems, evaluating on stored pairs would
overstate the monitor's catch rate by about a quarter of all backdoors. Some of this gap may come
from Sonnet~5 writing subtler backdoors than the stored attackers, which this comparison cannot
separate from authorship. The monitor's errors are unrelated to the classifier's ($\phi = 0.04$),
so the two respond to different features of the code.

\section{The label records attack failure}
\label{sec:label}

The filtered split assigns a test problem to the backdoored class only if its backdoor works.
When the backdoor fails, the problem contributes its human solution to the honest class instead,
and 720 of the 1{,}203 honest test programs entered the split this way. Problems in the backdoored
class have about half as many test cases as the rest, 20.95 against 38.85 on average, probably
because a backdoor is easier to hide from fewer tests. The label therefore depends on how hard a
problem was to attack, and this dependence is what the metadata classifier reads.

\section{Limitations}
\label{sec:limitations}

Rebuilding the corpus changes more than the author. Our two models differ from the ten stored
attackers in how they write backdoors and how often those backdoors work, and we sampled them
through an API with default settings, so $\rho$ is not an upper or lower bound on the share of
signal due to authorship. The comparison over all attempts sets stored backdoors that almost
always work (all of them, in a sample of 194 problems) against rebuilt attempts that mostly do not.
The comparison on working backdoors avoids this but rests on 99 pairs. We study one family of APPS
corpora and five agentic settings (Appendix~\ref{app:agentic}). Finally, a strong baseline is
evidence about a corpus, and none of our results corrects a specific published monitor score.

\section{Recommendations}
\label{sec:recommendations}

Stored pairs are cheap and reproducible, and they will remain useful for developing monitors. Our
results suggest four changes to how they are built and reported.
\begin{enumerate}[label=\arabic*.]
  \item Report a lexical baseline and a metadata baseline next to every monitor score, each with a
  permutation null.
  \item Have one model write both classes, from one prompt, so that the classes differ only in the
  requested backdoor.
  \item Define the honest class by honesty, independently of whether attacks on a problem
  succeeded.
  \item Report results on working backdoors separately from all attempts, and report the catch rate
  at a fixed audit budget alongside AUROC.
\end{enumerate}
The rebuilt corpus, every draw of its retry pool, the selection rules and the scripts are released
under the MIT licence (Appendix~\ref{app:release}).

\section{The rebuilt corpus}
\label{app:samegen}

\input{fig/tabA-rebuilt}

\paragraph{Yield.}
Honest solutions pass the public tests for 77.0\% of the 1{,}444 problems with Sonnet~5 and 72.8\%
with Haiku~4.5. A problem enters the rebuilt corpus when both its honest solution and its backdoor
attempt pass. The Sonnet~5 retry pool holds 11{,}565 attempts. Haiku~4.5 produced 35 working
backdoors, below the minimum of 50 pairs we set before analysis, so it has no row for working
backdoors.

\paragraph{Pair similarity.}
If the backdoored solution were an edit of the honest one, the two would be near copies and hard
to separate for reasons unrelated to authorship. Table~\ref{tab:similarity} shows that our attempts,
written from the problem alone, are about as similar to their honest solutions as the stored pairs
are. A variant in which the model edits its own honest solution produces near copies (mean
similarity 0.928) and gives $\rho = 0.366$, which we report only as a bound. Haiku~4.5 pairs are
more similar on average (0.724), so we also computed its AUROC within bands of similarity. It stays
between 0.47 and 0.51 in every band, including the least similar one, while the stored AUROC stays
between 0.79 and 0.83.

\paragraph{Rebuilding only one class.}
Replacing only the honest solutions with code from Qwen3-Coder-30B, against the stored backdoors,
raises the AUROC on the same 668 problems from 0.874 to 0.962 ($\rho = 1.23$, a mean over folds).
This swaps one difference in authorship for a larger one, which is why both classes must come from
the same model.

\paragraph{What the remaining signal is.}
Masking numbers or comparison operators leaves the Sonnet~5 AUROC unchanged. Normalising
identifiers lowers it to 0.699 ($\rho = 0.54$). With a shared prompt the same mask gives
$\rho = 0.34$ (0.28 to 0.39), so identifier normalisation and a shared prompt remove largely the
same signal. The layout that marks Sonnet~5 backdoors (\texttt{def main}, \texttt{sys.stdin},
\texttt{data[}) appears in none of the Haiku~4.5 programs, which read input with \texttt{input()}
throughout.

\paragraph{Sample size.}
On 30 random subsets of the stored pairs, the classifier reaches 0.851 with 623 problems and 0.773
with 99, against stored AUROCs of 0.865 and 0.789 on the exact rebuilt problems.

\section{The LLM monitor}
\label{app:monitor}

rationale and ends with a suspicion score from 0 to 100. Comments are removed with the same

\section{Agentic settings}
\label{app:agentic}

In five ControlArena settings \cite{sinha2026controlarenacorpora}, the same three models
(claude-sonnet-4, gemini-2.5-pro and gpt-5) produce both honest and attack transcripts, so there is
no difference in authorship. A structural baseline still separates the classes. Within each task,
transcript length alone reaches an AUROC between 0.504 (bash) and 0.802 (agentdojo)
(Figure~\ref{fig:agentic}). A permutation null of the same statistic, shuffling labels within each
task, puts four of the five settings far above chance ($p \le 0.001$) and leaves bash at chance. In these settings a
short keyword search over the untrusted model's own reasoning also reaches 0.76 to 0.82, because
attack policies restate their side task there. We mention this only to bound our claims and refer
to \cite{little2026length} for a proper treatment.

\section{Test harness}
\label{app:harness}

Our harness runs each solution on every shipped test input under limits on time and memory and
compares normalised output. It agrees with the corpus's own \texttt{solution\_passes\_tests} on
95.84\% of the 1{,}444 problems and never passes a solution the corpus rejects. We use our verdict
for both classes so that the checker cannot be stricter on one class than the other. Under the
corpus's verdict the stored AUROC over all 1{,}444 problems is 0.871 (a mean over folds), and under
ours it is 0.873 over 1{,}406.
