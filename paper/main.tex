\begin{abstract}
AI-control monitors are tuned and ranked on fixed datasets of paired programs, each pair an honest
solution and a backdoored solution to the same programming problem. We show that scores on these
datasets partly measure how the pairs were built rather than whether a monitor detects sabotage.
In the public APPS datasets, people wrote the honest code and language models wrote the backdoors.
A bag-of-words classifier that cannot recognise a backdoor reaches AUROC \tfidfKoran{} on a
standard split, above \tfidfKoranCount{} of \monN{} published monitors. The split's labels leak as
well, because a problem whose backdoor failed is labelled honest, so problem metadata alone
predicts the label. When one model writes both classes, the classifier's advantage over chance
falls by about a third with Claude Sonnet~5 and by nine tenths with Claude Haiku~4.5, and swapping
one class at a time shows that the fall comes from authorship. An LLM monitor drops for a
different reason. At a 2\% audit budget it catches \auditStrictOurs{} of our working backdoors
against \auditStrictStored{} of the original ones, and it finds ours less suspicious. We
release the rebuilt pairs and recommend four changes to how these benchmarks are built and
reported.
\end{abstract}

\section{Introduction}

AI control asks how to use a capable model safely even if it tries to cause harm
\cite{greenblatt2023aicontrol}. Its main safeguard is trusted monitoring. A weaker model that we
trust reads each output of the stronger, untrusted model and flags suspicious ones for a human to
audit. In the standard testbed the untrusted model writes solutions to programming problems and may
hide a backdoor, code that passes the tests but gives a wrong answer on an input the attacker
chooses. Monitors are developed and ranked on fixed datasets of such code. Each problem contributes
an honest solution and a backdoored one \cite{koran2026ensemble, terekhov2025controltax,
jha2026decorrelation}, and we call these the \emph{original pairs} (Figure~\ref{fig:pairs}).

\input{fig/f5-stored-pairs}

The original pairs differ in a way that has nothing to do with sabotage. People wrote the honest
solutions, taken from APPS \cite{hendrycks2021apps}, and language models wrote every backdoor. Human
and model code differ in spacing, naming and layout (Figure~\ref{fig:pairs}), and these differences
are easy to detect \cite{orel2026aicd}. A detector can therefore separate the classes by recognising
the author instead of the backdoor. The same failure is familiar elsewhere. Language inference models
classify from the hypothesis alone \cite{gururangan2018annotation, poliak2018hypothesis}, simple cues
predict answers on many LLM benchmarks \cite{pacchiardi2024cleverhans, kaushik2018howmuch}, and
benchmarks for detecting model-written code match their classes on problem and length for this
reason \cite{guo2025codemirage, demirok2025multiaigcd}. Backdoor datasets remove only the most
visible cue, the comments \cite{koran2026ensemble, jha2026decorrelation}. Other control work studies
injected text, attack selection and transcript length \cite{terekhov2026adaptive,
gewang2026attackselection, pinto2026calibration}, but not who wrote each class.

We argue that scores on the original pairs measure how the pairs were built as well as whether a
monitor detects sabotage, and we trace the extra signal to three choices.
\begin{itemize}
\item \textbf{Who wrote each class.} A bag-of-words classifier, which cannot recognise a backdoor,
beats \tfidfKoranCount{} of \monN{} published monitors on the standard split, works almost as well on
backdoors that never trigger, and transfers between attacking models (\S\ref{sec:results}). When one
model writes both classes its advantage over chance falls, and swapping one class at a time shows
that the fall comes from authorship (\S\ref{sec:samegen}).
\item \textbf{How the labels were assigned.} A problem whose backdoor failed is labelled honest, so
a classifier that reads only problem metadata also beats most monitors (\S\ref{sec:label}).
\item \textbf{How conspicuous the backdoors are.} An LLM monitor also drops on the rebuilt pairs,
but its drop follows the backdoors rather than the author. At a 2\% audit budget it catches
\auditStrictStored{} of the original working backdoors and \auditStrictOurs{} of ours
(\S\ref{sec:swap}).
\end{itemize}
We release the rebuilt pairs and the scripts behind every number,\footnote{Code and data:
\url{https://github.com/ShubsDS/authorship-not-sabotage}.} and close with four changes to how such
datasets are built and reported. Our claims concern monitors developed on fixed datasets;
ControlArena \cite{controlarena}, which generates both classes live, is not affected.

\section{Setup}
\label{sec:setup}

\paragraph{The dataset.} We study the public APPS backdoor dataset \cite{inglis2025appscontrolarena}
in its full and filtered releases (appendix~\ref{app:schema}). People wrote its honest solutions, and
\storedAttackers{} named models or an unattributed source wrote its backdoors
(appendix~\ref{app:attackers}). The standard split \cite{koran2026ensemble, koran2026highquality},
which we rebuild with the released code \cite{jha2026decorrelation}, has \splitTrain{} training
problems with one solution of each class and \splitTest{} test solutions (\splitAttack{}
backdoored). It labels each test item by whether its backdoor works. For our own pairs we use the
\baselineBn{} problems of the full release that have a passing human solution, a working backdoor
and deterministic tests. Six of the seven datasets we touch, including five agentic settings in
appendix~\ref{app:agentic}, have no licence, so we report aggregates only
\cite{sinha2026controlarenacorpora}.

\paragraph{Two baselines that cannot see a backdoor.} The \emph{bag-of-words} classifier is a
logistic regression on word and word-pair frequencies (TF-IDF) of the code, with comments removed.
The \emph{no-code} classifier is a logistic regression on three facts about the problem, its
difficulty, number of test cases and statement length, and never sees code. We call the AUROC of
such a baseline a \emph{floor}. A monitor at or below the floor has shown nothing beyond what the
dataset gives away. Each floor is compared with its score on shuffled labels (1{,}000 shuffles).

\paragraph{Rebuilt pairs.} To remove the difference in authors, one model, Claude Sonnet~5 or Claude
Haiku~4.5, writes both solutions to each problem. It writes an honest solution and, in a separate
request that sees only the problem, a backdoored solution with an input meant to trigger it. Our
test runner checks both (appendix~\ref{app:harness}). A backdoor \emph{works} if it passes the public
tests and gives a wrong answer on its trigger input. We report two sets. \emph{All attempts} keeps
one backdoor per problem, chosen before we know whether it works, as the benchmark does.
\emph{Working backdoors} keeps only backdoors that work, drawn from repeated tries. In a
\emph{prompt-matched} version the honest solution is requested with the backdoor prompt itself,
minus the request for a flaw, so the two requests differ only in that clause.

\paragraph{Measuring what survives.} We fit the same bag-of-words classifier to the rebuilt pairs and
to the original pairs of the same problems. Since 0.5 is chance, we report
$\rho = (\text{rebuilt AUROC} - 0.5)/(\text{original AUROC} - 0.5)$, the fraction of the
classifier's advantage over chance that remains when one model writes both classes. At $\rho = 1$
nothing is lost; at $\rho = 0$ the classifier is at chance. The rebuild changes the backdoors as well
as the author, so $\rho$ is not the share of the signal due to the backdoor. AUROCs come from
five-fold cross-validation with 95\% bootstrap intervals over problems (appendix~\ref{app:stats}),
and we fixed two thresholds, $\rho = \rhoCollapse{}$ and $\rho = \rhoContent{}$, before any run.

Trained on the split's training problems and tested once, the bag-of-words classifier reaches AUROC

\tfidfKoranCount{} of the \monN{} published monitors, whose median is \monMedian{}, and

The monitors are prompted while the classifier is trained on the benchmark, so this does not make
the classifier a better monitor. It shows how much the dataset gives away.

The classifier is not finding backdoors, for three reasons (appendix~\ref{app:protocol}). Trained on
one attacking model's backdoors, it recognises another model's in \transfer{} of pairs, so it reads
something all attackers share. It separates backdoors that never trigger almost as well as working
ones (\pairInert{} against \pairWorking{} of pairs). And its strongest features are generic. On the
backdoor side they are \texttt{and}, \texttt{==} and \texttt{if}, the tokens of any added special
case, and on the honest side human idioms such as \texttt{for i} and \texttt{while}
(Figure~\ref{fig:features}). Removing comments does remove the cue it targets, since a detector that
counts comments falls from \hashRaw{} to \hashStripped{}. Other style cues remain. For example,
\texttt{\_\_main\_\_} appears in 11.6\% of test backdoors and in no honest solution.

\subsection{The labels record which attacks failed}
\label{sec:label}

The split puts a test problem in the backdoor class only if its backdoor works. If the backdoor
fails, the problem contributes its human solution to the honest class instead, and this happens for
\inertShare{} of the split's backdoors. The label therefore depends on how hard a problem was to
attack, which is visible without reading code. Backdoor-class problems have about half as many test
cases as honest ones (\testCasesAttack{} against \testCasesHonest{}; Figure~\ref{fig:floors-c}).
Cross-validated within the test split, the no-code classifier reaches \nocodeCV{}, above
\nocodeCVCount{} monitors. Trained on problems outside the split it scores \nocodeOutside{}, below
chance (Figure~\ref{fig:floors-b}), because outside the split every problem has a working backdoor
and the relation between test count and label reverses. The no-code classifier measures how the
labels were chosen, not anything in the code.

\section{Limitations}

A high floor shows that a dataset's labels can be predicted without finding a backdoor, not that any
monitor predicts them that way, and nothing here corrects a published monitor score. Which model
wrote the original backdoor matters on its own. Against the same human code it moves the original
AUROC from \bAttackerLo{} to \bAttackerHi{}, although $\rho$ hardly depends on it (Claude attackers
only, \rhoClaudeOnly{}; appendix~\ref{app:attackers}). Our monitor results concern backdoors written
under our prompt, and the comparison of working backdoors rests on \strictN{} pairs from one
model.\footnote{Three of these \strictN{} backdoors differ from the classifier's; without them the
monitor's AUROC is \monStrictMatched{} instead of \monitorStrict{} (appendix~\ref{app:monitors}).}
The rebuilt pairs cannot be reproduced bit for bit, because the API hides sampling parameters. We
study one APPS dataset family and five agentic settings repackaged from ControlArena by one user;
other datasets are untested. Two artifacts of older Python versions in the human solutions give the
original pairs a small extra cue (appendix~\ref{app:harness}).

\section{Recommendations}

Fixed datasets of pairs are the cheapest way to develop a monitor. Four changes would make the
scores they produce easier to interpret.
\begin{enumerate}
\item Report the bag-of-words and no-code floors beside every monitor score, each with its
shuffled-label baseline, so readers can see how much of the score the dataset gives away.
\item Have one model write both classes from the same prompt, and check both with the same tests, so
that the backdoor is the only intended difference.
\item Choose honest examples independently of whether an attack on the problem succeeded, or drop
the problems whose attacks failed.
\item Report the share of backdoors caught at a fixed audit budget, separately for working backdoors
and all attempts, with the share of backdoors that work.
\end{enumerate}
Otherwise a monitor's score may describe how the pairs were built rather than the monitor. Our
pairs, retry pool and scripts are released under the MIT licence (appendix~\ref{app:release}).

\subsection{Running the code}
\label{app:harness}
Rebuilding the pairs means running generated code. Our runner feeds each of a problem's stored test
inputs to a solution, with a time limit per input and a memory limit. It agrees with the dataset's
\texttt{solution\_passes\_tests} flag on \harnessAgreement{} of the \baselineBn{} problems we analyse
and is stricter, never passing a solution the dataset fails (\harnessFailWePass{} cases). We use our
runner for both classes, because a checker that rejects one class more readily would create exactly
the kind of class difference this paper is about. The choice does not change the original AUROC,
which is \baselineB{} on \baselineBn{} pairs under the dataset's flag and \baselineBownflag{} on
\baselineBownflagN{} pairs under ours. We do not match program lengths; each model chooses its own.

Two quirks of older Python versions appear in the dataset's solutions, on opposite classes. Reading
\texttt{stdin} without \texttt{.buffer} we can fix; \texttt{fractions.gcd}, removed in Python~3.9, we
cannot. These quirks give the original pairs a small extra cue that the rebuilt pairs, which we
generated and ran ourselves, do not have. The monitor scores in Figure~\ref{fig:monitors} are
\texttt{runs/x0/monitor-summary.json} from the MIT release of the monitor-ensemble harness
\cite{jha2026decorrelation}, used under its notice.

\subsection{Statistics}
\label{app:stats}
\paragraph{Cross-validation.} Most AUROCs come from five-fold cross-validation with folds split by
problem. Each item is scored by the model fitted without its fold, and one AUROC is computed over all
these scores. The no-code classifier inside the test split also averages over five repeats of the
folds. Bag-of-words on the standard split, the no-code classifier trained outside it, and the
monitors score each item once, without folds.

\paragraph{Intervals.} Every interval is a 95\% percentile bootstrap over problems, \bootDraws{}
draws, seed 0. For $\rho$, each draw resamples one set of problems and recomputes both AUROCs on it,
so the interval reflects how the two move together; we call this a joint interval. Differences (a
floor against a monitor, original against rebuilt pairs) are computed on the same draws. We chose the
bootstrap, over an earlier rule of two fold standard deviations, before looking at the retries
behind the working-backdoor rows.

\paragraph{Shuffled labels.} Each permutation test shuffles the labels, reruns the whole pipeline
including fitting, and recomputes the statistic, \permReps{} times, with
$p = (1 + \#\{\text{shuffled} \ge \text{observed}\})/(1 + \permReps{})$. In the agentic settings labels
are shuffled within each main task (appendix~\ref{app:agentic}); the token test uses random token
sets instead (appendix~\ref{app:token}). No per-pair scores were kept for the edit variant, so its
$\rho$ has no joint interval.

\subsection{What we release}
\label{app:release}
The release bundle is attached to the \texttt{v1.0} release of the code repository, under the MIT
licence for both data and scripts. It contains
\begin{itemize}
\item the rebuilt pairs: \relHonest{} honest programs, \relEdit{} edit-variant and \relIndep{}
independent-variant backdoored programs, and all \relRetryDraws{} draws from the retries;
\item two selections of pairs. The first keeps the first draw for each problem (\relPassFirst{}
passing pairs, \relFireFirst{} with a working backdoor). The second keeps the earliest retry that
works (\relPassBest{} and \relFireBest{}, or \relFireBestCrash{} if a crash on the trigger input
counts as working), because the original backdoors are also the survivors of retries;
\item the \relScripts{} scripts behind every number, from generation and testing to the monitor runs
and class swaps;
\item a dataset card and a manifest of row counts and checksums.
\end{itemize}

\subsection{A token test that does not replicate}
\label{app:token}
\citet{orel2026aicd} report that a small set of tokens separates human from model code. In our data
it does not. The separation is \tokenSep{}, the wrong sign, with permutation $p = \tokenP{}$. We
think the reason is the kind of code. Their human class is general repository code, whereas both
our classes are competitive-programming solutions, so tokens that mark general human code do not
separate them. Only 8 of their 10 tokens occur in our data, so the test has little power, but a real
effect should still have the right sign. We report it because readers who know that work may try
the same test.

\subsection{Checks on the drop}
\label{app:robust}
\paragraph{It is not sample size.} On 30 random subsets of the original pairs, run through the same
pipeline, the AUROC is $\three{\curveHeadline} \pm \three{\curveHeadlineSd}$ (mean $\pm$ SD) at
$n = \sameGenN{}$, far above the \three{\sameGenS} of the rebuilt pairs. At $n = \strictN{}$, the
size of the working-backdoor row, it is $\three{\curveStrict} \pm \three{\curveStrictSd}$, so the
classifier itself loses accuracy at that size. This is why $\rho$ divides by the AUROC refitted on
the original pairs of the same problems. Reassigning problems to folds with five seeds gives the
working-backdoor row a $\rho$ of \strictRhoSeeds{} (\strictRho{} in Table~\ref{tab:gates}).

\paragraph{It is not numbers or operators.} We masked three kinds of token in both classes: numbers,
comparison operators and identifiers. Only masking identifiers changes the all-attempts row's
rebuilt AUROC, to \sameGenSid{} ($\rho = \sameGenRhoId{}$, \sameGenRhoIdLo{}--\sameGenRhoIdHi{}); the
other two masks move it by at most \maskMaxShift{}. Code length alone separates that row's rebuilt
pairs at \three{\sameGenLen}.

\paragraph{It is not whether the backdoor works.} Within our backdoored class, draws that work and
draws that do not separate at only \survivorAuroc{}. On the working-backdoor problems, putting
failed attempts in place of the working backdoors gives a rebuilt AUROC of \three{\survivorSwapS},
against \three{\survivorSwapSref} with the working backdoors.

\paragraph{Other ways to rebuild.} The edit variant, whose pairs are near-copies, gives
\three{\editS} over \editN{} pairs, $\rho = \editRho{}$. Regenerating only the honest class, with
Qwen3-Coder-30B, raises the AUROC to \armOneG{} against \armOneBprime{} on the original pairs of the
same \armOneN{} problems, while code length alone falls to \armOneLenG{}.

\paragraph{Why our backdoors rarely work.} In \trigPublicShare{} of our draws that pass the public
tests, the model names a public test input as its trigger. A solution that passes the public tests
cannot fail on such an input. Of these draws \trigPublicFire{} work, against \trigNovelFire{} of
draws with a new trigger input, so our prompt roughly halves the share of backdoors that work. No
working original backdoor uses a public test input as its trigger (\trigStoredPublic{}).

\subsection{Do working backdoors raise $\rho$?}
\label{app:shared}
They do not. Sonnet~5's all-attempts and working-backdoor rows differ in two ways: in the second
row the backdoors work, and it covers only problems where a working backdoor could be drawn. The
\sharedN{} problems in both rows separate the two effects, since on them the honest program and the
original pair are the same and only our backdoor differs. We reuse the existing out-of-fold scores
on these subsets without refitting (Table~\ref{tab:shared}).

On the shared problems $\rho$ is \sharedRhoHead{} with the sampled attempts and \sharedRhoWorking{}
with the working backdoors (paired difference \sharedDiffLo{} to \sharedDiffHi{}). Restricted to the
\shDiffN{} problems where the two backdoors differ, it is \shDiffHeadRho{} and \shDiffWorkRho{}
(difference \shDiffDelta{}, \shDiffDeltaLo{} to \shDiffDeltaHi{}). On the other \shSameN{} the
sampled backdoor already works and is the same program in both rows. Working backdoors lower the
point estimates, and both intervals include zero.

The problems matter more. The \shStrictOnlyN{} problems found only in the working-backdoor row give
$\rho = \shStrictOnlyRho{}$ (\shStrictOnlyRhoLo{}--\shStrictOnlyRhoHi{}), with a lower original AUROC
(\shStrictOnlyBp{} against \shWorkBp{}) and a higher rebuilt one (\shStrictOnlyS{} against
\shWorkS{}) than the shared problems. The difference, \shOnlyMinusShared{} (\shOnlyMinusSharedLo{}
to \shOnlyMinusSharedHi{}), is not resolved at this size, but by point estimate the higher $\rho$ of
the working-backdoor row comes from which problems yield a working backdoor.

($\rho = \matchedRhoId{}$) and the same \matchedN{} problems without prompt matching to
\three{\matchedSidOrig}. Whether what remains is program structure or naming is undecided: the
masked row's interval, \matchedRhoIdLo{}--\matchedRhoIdHi{}, straddles the threshold
$\rho = \rhoCollapse{}$ fixed in advance. A character-level model (3 to 5 characters, same classifier
and folds) keeps more than the word model, \three{\matchedChar} ($\rho = \matchedRhoChar{}$), so the
drop does not come from how code is split into words. Under the two prompts, Sonnet~5's correct
honest solutions separate at \promptOnly{}.

\paragraph{Haiku~4.5's low AUROC is not caused by near-copies.} Its rebuilt pairs are more alike than
Sonnet~5's (mean similarity \haikuPairSim{} against \simIndep{}), so we recomputed its rebuilt AUROC
within bands of similarity. It stays at \haikuStrataS{} in every band, including the band at
\haikuStrataLowSim{}, whose pairs are less alike than the original pairs, while the original AUROC on
the same problems stays at \haikuStrataBprime{}. Its honest solutions under the two prompts separate
at only \three{\haikuPromptFloor}. Haiku~4.5 never uses the layout that marks Sonnet~5's backdoors.
\texttt{def main}, \texttt{sys.stdin} and \texttt{data[} appear in none of its programs in any
class, and every program reads input with \texttt{input(}, so no layout difference is left to
read.

\subsection{How often each model's code passes and works}
\label{app:counts}
Both models ran through the same pipeline. Their honest solutions pass the public tests on
\three{\sonnetHonestPass} (Sonnet~5) and \three{\haikuHonestPass} (Haiku~4.5) of 1{,}444 problems.
Haiku~4.5's backdoored solutions pass on \haikuAttackPass{} problems, and only \haikuUsable{} of them
work, below the 50 pairs we required, so Haiku~4.5 has no working-backdoor row. In the all-attempts
rows \haikuFireInRow{} of Haiku~4.5's \haikuN{} backdoors work, against \relFireFirst{} of
Sonnet~5's \sameGenN{}. Haiku~4.5's other \haikuUsableOutside{} working backdoors are on problems
where its own honest solution failed, which therefore have no rebuilt pair.

\paragraph{Rescoring is noisy.} The four cells combine separate batches, submitted about six hours
apart on the same day for Sonnet~5. The monitors sample at default settings. On programs scored in

draw that works without crashing. Dropping the three moves the monitor's \monitorStrict{} to
\monStrictMatched{}.

\section{Agentic settings}

\subsection{Length leaks the label even with one set of authors}
\label{app:agentic}
A dataset can leak its labels without any gap between authors. In five agentic settings where the
same three models (claude-sonnet-4, gemini-2.5-pro and gpt-5) write both classes, character count
alone separates the classes within each task, with AUROC from \bashFloor{} (\texttt{bash}, at chance)
to \agentdojoFloor{} (\texttt{agentdojo}; Figure~\ref{fig:corpora}). We compute it within each main
task because a pooled AUROC would also read which task each item came from.

\includegraphics{f2-corpus-floors.pdf}

\subsection{A third cue in agent reasoning}
In the same five settings, a fifteen-word regular expression over the untrusted agent's own
scratchpad reaches AUROC \cotLow{}--\cotHigh{}, because prompted attack policies restate their side
task in the reasoning the monitor sees. We mention it only to mark the edge of our claim.
\citet{little2026length} developed and validated this method against an LLM judge and a
length-matched baseline.
