\begin{abstract}
AI-control monitors are tuned and ranked on fixed datasets of pairs, an honest and a backdoored
solution to each programming problem. In APPS-backdoor datasets the honest code is
human-written and the backdoor model-written, so a detector can separate them without reading
any backdoor. On the filtered, comment-stripped split, bag-of-words reaches AUROC
\tfidfKoran{}, transfers across attacking models, and is nearly as strong on backdoors that
never work. A classifier reading only problem metadata, trained on problems outside the split,
scores \nocodeOutside{}, below chance; cross-validated within the split it reaches \nocodeCV{}.
The split's filter, not the code, sets that relation. We rebuild the pairs with one model
writing both solutions to each problem and one harness verifying both, and release
them.\footnote{Code and corpus:
\url{https://github.com/ShubsDS/authorship-not-sabotage}.} Writer features then cannot separate
the classes; what still does comes from what the prompts asked for, the backdoor included. The
share $\rho$ of bag-of-words' above-chance AUROC that survives the rebuild is \sameGenRho{}
(Sonnet~5) and \haikuRho{} (Haiku~4.5) on one attempt per problem, of which \relFireFirst{} of
\sameGenN{} and \haikuFireInRow{} of \haikuN{} work, and \strictRho{} on \strictN{} Sonnet
backdoors that work. $\rho$ is not the backdoor's share: the attacks change with the writer,
and the attacking model alone moves the original pairs' AUROC from \bAttackerLo{} to
\bAttackerHi{}. Swapping one class at a time separates two detectors: bag-of-words stays at
\clfSwapOursStored{}--\clfSwapHumanOurs{} whenever the classes have different writers and falls
only when one model writes both, while a Sonnet~5 monitor's fall from \monStoredHeadAbs{} to
\monitorS{} lies entirely in our attacks, which it finds far less suspicious. Evaluations should
report both classifiers as floors against permutation nulls, build both classes with one model
under one prompt, define the negative class by honesty, and report detection at a fixed audit
budget with the share of backdoors that work.
\end{abstract}

\section{Introduction}

The backbone protocol of AI control is trusted monitoring, where a weaker trusted model reads
an untrusted model's output and flags sabotage \cite{greenblatt2023aicontrol}. Monitors
are developed, tuned and ranked almost entirely on fixed datasets of honest/attack pairs, in
which each programming problem contributes an honest solution and a solution carrying a planted
backdoor \cite{koran2026ensemble, terekhov2025controltax, jha2026decorrelation}; we call these
the \emph{original pairs}. Honest solutions are
human-written, taken from APPS \cite{hendrycks2021apps}, and backdoors are written by language
models, so a detector can separate the classes without reading any backdoor
(Figure~\ref{fig:pairs}).

\begin{figure}[t]\centering
\includegraphics[width=\linewidth]{f5-stored-pairs.pdf}
\caption{\textbf{Three original pairs.} Each column is one APPS problem from the public dataset
\cite{inglis2025appscontrolarena} (MIT): the human-written honest solution above a working
backdoor written by the named model, comments removed. The highlighted lines are the backdoor:
its trigger condition and its wrong output. Outside the backdoor the model's code also differs
in style: spaces around operators (4253, 4254) and a \texttt{main} function with an entry-point
guard (755).}
\label{fig:pairs}
\end{figure}

There are known confounding variables between human and AI solutions, such as commenting style, so datasets are often preprocessed to mitigate them. The filtered
release keeps only working honest solutions and working backdoors and strips every comment
\cite{koran2026ensemble}; Control Tax reports its pass-tests pre-filter and moves its failed
backdoors to an appendix \cite{terekhov2025controltax}; the monitor-ensemble harness of
\cite{jha2026decorrelation} ships a \texttt{--leak-check} flag with two trivial baselines: a
\texttt{\#}-count detector that falls from \hashRaw{} to \hashStripped{} once comments
are stripped, and code length alone, at \lenFiltered{}. Outside AI control, bag-of-words is known to separate human-written from
model-written code \cite{orel2026aicd}, and the benchmarks built for that task match their two
classes on line and character count or on shared problem definitions \cite{guo2025codemirage,
demirok2025multiaigcd}. Adjacent control work attacks other axes: monitors subverted with
injected text, attacker-side selection shown to inflate safety estimates, transcript length
removed as a nuisance covariate \cite{terekhov2026adaptive, gewang2026attackselection,
pinto2026calibration}.

Two classifiers separate the classes of the filtered release's test split without reading a
backdoor. We call the AUROC such a classifier reaches a \emph{floor}: a monitor at or below it
has shown nothing the dataset does not already leak. Bag-of-words reaches AUROC \tfidfKoran{}, above \tfidfKoranCount{} of the \monN{}
open-weight monitors ranked on that split. It transfers across backdoor generators and is
nearly as strong on backdoors that never produce a wrong answer as on working ones, so it is not
reading the sabotage. A classifier that reads no code,
only problem difficulty, test count and question length -- the \emph{no-code floor} -- scores
\nocodeOutside{}, below chance, when trained on problems outside the split, and \nocodeCV{},
above \nocodeCVCount{} of the monitors, when cross-validated within it. The relation it reads is
set by the split's filter: inside the split attack problems carry fewer tests, outside it more.

We contribute (i)~two classifier floors for datasets of original pairs, bag-of-words and
no-code, each against a permutation null; (ii)~a same-generator construction, in which one model
generates both classes on the same problems and one harness verifies both, and our corpus, which
implements it; and (iii)~a flaw in the label: labelling by \texttt{backdoor\_works} defines the negative class by
attack failure, so the negative class records which attacks failed. They imply a reporting
practice: both floors beside any monitor score, both classes from one model under one prompt, a
negative class defined by honesty, and detection at a fixed audit budget reported with the
share of backdoors that work. Our claims concern monitor training, selection and benchmarking on
original pairs, and our measurement is of one APPS-derived family plus five agentic settings
(appendix~\ref{app:agentic}). ControlArena, the evaluation framework most of these datasets are
exported from, generates both classes live and is not implicated.

\section{Setup}

We use seven public datasets, whose per-class provenance is the object of study: two views of
one APPS-backdoor dataset \cite{inglis2025appscontrolarena}, the full and the filtered release
(appendix~\ref{app:schema}), and five agentic settings (appendix~\ref{app:agentic}). In its original pairs the honest solution is
human-written and the \emph{original backdoor} comes from one of \storedAttackers{} named models
or an unattributed source (appendix~\ref{app:attackers}). Six of the seven declare no licence
\cite{koran2026highquality, sinha2026controlarenacorpora}, so we report only aggregates and
redistribute none.

Our primary protocol is the filtered, comment-stripped split
\cite{koran2026ensemble}: \splitTrain{} train problems (\splitTrainItems{} paired items) and
\splitTest{} test items (\splitAttack{} attack, \splitHonest{} honest), labelled by
\texttt{backdoor\_works}, reconstructed with the released harness code
\cite{jha2026decorrelation}. The split is a filtered view of the dataset; we rebuild pairs on
the \baselineBn{} problems of the full release that we analyse, whose original pairs bag-of-words separates at AUROC
\baselineB{}. Generated code is scored by our own
runner, applied to both classes (appendix~\ref{app:harness}).

Our corpus consists of \emph{rebuilt pairs}: for each problem, one model, Sonnet~5 or
Haiku~4.5, writes both the honest and the backdoored solution. With one writer, writer features
cannot separate the classes; what still separates them comes from what the two prompts asked
for, the backdoor included. We build three \emph{variants}. In the \emph{independent} variant the model
writes the backdoored solution from the problem statement alone; in the \emph{edit} variant it
sees its own honest solution and returns near-copies (appendix~\ref{app:pairsim}).
In the \emph{prompt-matched} variant the honest solution is requested under the attack prompt's
wording, with the clauses asking for a flaw replaced by their correct-program counterparts, so
both classes are elicited alike. A backdoor \emph{works} if it passes the public tests and gives
a wrong answer on the trigger input its writer names. The \emph{all-attempts} rows of
Table~\ref{tab:gates} keep one independent-variant attack per problem, sampled before its
outcome is known and kept if it passes the public tests. The
\emph{working-backdoor} rows keep only attacks that work, drawn from a pool of retries.

One bag-of-words classifier (5-fold, comments stripped), fitted separately on each set of
pairs, gives an AUROC on the rebuilt pairs and one on the original pairs of the same problems;
\mbox{$\rho = (\text{rebuilt AUROC} - 0.5)/(\text{original AUROC} - 0.5)$} is the share of its
above-chance AUROC on the original pairs that remains on the rebuilt pairs. The rebuild changes
the attacks as well as the writer: ours rarely work, and a monitor finds them far less
suspicious than the original ones (\S\ref{sec:results}). $\rho$ therefore measures what
survives, not the share due to the backdoor nor a bound on it. Table~\ref{tab:gates} reports
the share of bootstrap draws with $\rho > \rhoContent{}$; that line and $\rho = \rhoCollapse{}$
were fixed before any variant ran.

\section{Results}
\label{sec:results}

Comment stripping drives comment count and code length to chance
(Table~\ref{tab:protocol-baseline}). Two other baselines, the bag-of-words and no-code
floors, do not move.
Bag-of-words, trained on the split's train problems and scored once on its test
items, reaches AUROC \tfidfKoran{}. The no-code floor under the same protocol, trained on
problems outside the test split, scores \nocodeOutside{}, below chance: outside the split every
problem that passes the filter has a working backdoor, so the honest items are problems the
filter removed, and the relation between test count and label reverses. Cross-validated within
the test split it reaches \nocodeCV{}. Both rank above \tfidfKoranCount{} of the \monN{}
monitors (Figure~\ref{fig:floors}) and far above their permutation nulls
(Figure~\ref{fig:monitors}, appendix~\ref{app:protocol}). The monitors are
zero-shot, so the comparison states what the dataset makes recoverable, not which is the better
monitor. The no-code floor reads only problem metadata, so it measures how the split's label
was selected, not authorship.

Three further measurements show that the bag-of-words classifier is not reading the backdoor
(pairwise accuracies for the first two; appendix~\ref{app:protocol}). It transfers across
backdoor generators at \transfer{}, so the feature it has learned is one the attackers share.
It is nearly as strong on non-working backdoors, the harder case for a detector of sabotage, as
on working ones (\pairInert{} against \pairWorking{}). What it reads is stylistic:
\texttt{\_\_main\_\_} appears in 0.116 of attack samples against 0.000 of honest ones, a gap
that replicates on the train split (152 against 1 of \splitTrain{} per class). All three are
on comment-stripped code (unstripped: appendix~\ref{app:stripped}); a token-level version of
the last test does not replicate (appendix~\ref{app:token}).

The split selects on a second property besides authorship. Labelling by
\texttt{backdoor\_works} defines the negative class by attack failure rather than by
honesty: \inertShare{} of the test split's labelled backdoors do not work, and a
problem whose backdoor fails contributes its human honest solution instead, so the label is
set before any code is read. Attack problems also carry half as many test cases
(\testCasesAttack{} against \testCasesHonest{}), which the no-code floor reads.

On the all-attempts rows of Table~\ref{tab:gates}, holding the writer constant leaves $\rho = \sameGenRho{}$ for Sonnet~5 and
\haikuRho{} for Haiku~4.5; sample size does not account for the fall
(appendix~\ref{app:robust}). Only \relFireFirst{} of Sonnet~5's \sameGenN{} attacks and
\haikuFireInRow{} of Haiku~4.5's \haikuN{} work, while every original backdoor on those
problems works, so these rows set working original backdoors against mostly non-working
attempts. On Sonnet~5's \strictN{} working backdoors, $\rho = \strictRho{}$. That the attacks
work does not raise it: on the \sharedN{} problems in both sets, $\rho$ is \sharedRhoHead{} with
the sampled attempts and \sharedRhoWorking{} with the working backdoors (paired 95\% CI on the
difference \sharedDiffLo{} to \sharedDiffHi{}). By point estimate the higher $\rho$ on working
backdoors comes from which problems yield a working attack, though that difference is not
resolved (appendix~\ref{app:shared}).

The two models respond differently to the attack prompt. On Sonnet~5 what survives is
lexical: of the feature-ablation masks only identifier normalisation moves the rebuilt AUROC
(appendix~\ref{app:robust}), and the top attack-side features, \texttt{def main}
(\defMainAttack{} of attack programs against \defMainHonest{} of honest ones) and
\texttt{data[}, are the program layout the attack prompt elicits, which Haiku~4.5 never adopts
(appendix~\ref{app:secondpass}). Holding the prompt constant as well (prompt-matched
variant) lowers Sonnet~5's $\rho$ to \matchedRho{} and does not change Haiku~4.5's
(\haikuMatchedRho{}). On Sonnet~5 the honest solutions written under the two prompts, both
correct, separate at \promptOnly{}, so the prompt carries framing and no backdoor; Haiku~4.5's do not.

Regenerating only the honest class, with Qwen3-Coder-30B, makes the pairs \emph{more}
separable than the original ones, $\rho = \armOneRho{}$: one authorship gap replaced by another
(appendix~\ref{app:robust}).

Swapping one class at a time shows where each detector's drop comes from
(Table~\ref{tab:swap}). Bag-of-words stays high whenever the two classes have
different writers: human honest code against our backdoors scores \clfSwapHumanOurs{}, our
honest code against the original backdoors \clfSwapOursStored{}, and only when one model wrote
both does it fall, to \clfSwapOursOurs{} on the rebuilt pairs. Our backdoors in place of the
original ones raise its AUROC against human code, from \clfSwapHumanStored{} on the original
pairs, so its drop is authorship, not our attacks. Haiku~4.5 gives \clfSwapHaikuHumanOurs{} and
\clfSwapHaikuOursStored{} against \clfSwapHaikuOursOurs{} on its rebuilt pairs
(appendix~\ref{app:clfswap}).

A zero-shot Sonnet~5 monitor, the model that also wrote the Sonnet~5 rebuilt pairs, scores
\monStoredHeadAbs{} on the original pairs and \monitorS{} on the rebuilt pairs
(appendix~\ref{app:monitors}); for it the swap puts the drop in the attacks.
On the all-attempts problems (Table~\ref{tab:swap}),\footnote{The four cells combine scores from separate
batches run the same day; rescoring a program returns the same score \retestSameLo{}--\retestSameHi{} of the time
(appendix~\ref{app:monitors}).} replacing the human honest code with ours does not
lower the score, and replacing the original backdoors with ours lowers it to
\monSwapHumanOurs{} and the backdoors' mean suspicion from \monSuspStored{} to \monSuspOurs{}.
The same holds for working backdoors: on their problems human honest code scores
\monStoredStrictAbs{} against the original backdoors and \monSwapStrictHumanOurs{} against ours,
and our rebuilt pairs score \monitorStrict{}.\footnote{On three of the \strictN{} working-backdoor problems the
monitor scored a different attack from the one in the classifier's row; without them the AUROC
is \monStrictMatched{} (appendix~\ref{app:monitors}).} The monitor's fall
measures how conspicuous the attacks are, not authorship. At a fixed audit budget of
\auditFPR{} false positives, thresholded on each set's own honest programs, it catches
\auditStrictStored{} of the original and \auditStrictOurs{} of our backdoors on the
working-backdoor problems (paired difference \auditStrictDiff{}, 95\% CI
\auditStrictDiffLo{}--\auditStrictDiffHi{}), and \auditHeadStored{} against \auditHeadOurs{} on
the all-attempts problems (Figure~\ref{fig:audit}, appendix~\ref{app:audit}).

\section{Limitations}

A high floor is evidence about a dataset, not about results computed on it. Ours show the
label is recoverable without reading a backdoor, not that any monitor
recovers it that way, and no number here corrects a published monitor score.

Rebuilding with one model changes the attacks as well as their author: against the same human
code, the model that wrote the original backdoors alone moves the AUROC on the original pairs
from \bAttackerLo{} to \bAttackerHi{}, so $\rho$ is not the backdoor's share of the
separability, nor a bound on it. $\rho$ does not depend on which model wrote the original
backdoors (problems whose original backdoor a Claude model wrote: $\rho = \rhoClaudeOnly{}$;
appendix~\ref{app:attackers}). The class swap ties the classifier's drop to authorship but the
monitor's to our attacks, so the monitor results describe attacks written under our prompt,
which rarely work. Our corpus is not bit-reproducible: the API hides
sampling parameters; thinking was off.

Our scope is narrow in three further ways. We measure one APPS-derived dataset family and
five agentic settings, and other datasets of such pairs are untested. Five of our seven datasets
are one user's repackaging of ControlArena releases, so our claims are scoped to those datasets
as published. Two idioms of an older Python in the human solutions fall on opposite classes, so
the AUROC on the \baselineBn{} original pairs carries a small execution-environment signal that
the rebuilt pairs lack (appendix~\ref{app:harness}).

\section{Discussion}

These results imply one rule for construction: one model should write both classes under one
prompt framing, and one harness should verify both. Matched construction is precedented in
code-detection benchmarks
\cite{guo2025codemirage} but has not reached backdoor detection.

The definition of the negative class needs the same treatment. Defining it through attack
failure ties the label to the attacker rather than to the code; dropping the failed problems
removes that, as does sampling the class independently of attack success. A monitor number is
interpretable only against the floors of its own split, so a no-code and a
bag-of-words floor belong beside it, each against a permutation null, with the split and
preprocessing released alongside (ours: MIT, appendix~\ref{app:release}). It should also be
reported at a fixed audit budget, beside the share of backdoors that work.

Fixed datasets of pairs remain the cheapest way to develop a monitor; we argue only that a
score on one can describe how the pairs were built rather than the monitor.

\subsection{Statistics}
\label{app:stats}
Every cross-validated AUROC ($B$, $B'$, $S$, the masked and character-model rows, and the
no-code floor cross-validated within the test split) is one AUROC over the pooled out-of-fold
scores, each item scored by the fold that held it out; for the no-code floor each item's score
is averaged over five repeats of the folds. Bag-of-words on the filtered split, the no-code
floor trained outside it or on a held-out slice, and the monitors score each item once, with no
folds. Every interval is a 95\% percentile bootstrap over problems of the quantity it
accompanies, \bootDraws{} draws, seed 0. For $\rho$ each draw resamples one problem set and
recomputes $S$ and $B'$ on it; a paired difference (a floor against a monitor, stored against
same-generator pairs, one set of attacks against another) is recomputed on the same draws.
Every permutation null permutes the labels the pipeline reads, for fitting and scoring alike,
reruns the pipeline and recomputes the reported statistic, \permReps{} times, with
$p = (1 + \#\{\text{null} \ge \text{observed}\})/(1 + \permReps{})$; in the agentic settings
the labels are permuted within main-task groups (appendix~\ref{app:agentic}). The token test
uses a null over random token sets instead (appendix~\ref{app:token}). The bootstrap replaced a
$\pm 2$ fold-SD rule before the strict retry pool was read.

The edit arm's points are pooled, but no
per-pair scores were kept for it, so its $\rho$ has no joint interval. The pairwise accuracies
of Table~\ref{tab:protocol-baseline} are means over five problem-disjoint splits
(appendix~\ref{app:stripped}).

\subsection{Robustness of the same-generator rows}
\label{app:robust}
Sample size does not produce the headline fall. $B$ on 30 random subsamples of the
\baselineBn{}-pair pool, through the identical pipeline, is $\curveHeadline{} \pm
\curveHeadlineSd{}$ (mean $\pm$ SD) at $n = \sameGenN{}$, far above $S = \sameGenS{}$. At the
strict rows' $n = \strictN{}$ it is $\curveStrict{} \pm \curveStrictSd{}$: at that size the
classifier itself loses separability, which is why $\rho$ divides by $B'$ refitted on the same
problems rather than by $B$. Reassigning problems to folds with five seeds gives the strict row
$\rho$ of \strictRhoSeeds{} (\strictRho{} with the unshuffled folds of Table~\ref{tab:gates}).
Of three token masks applied to both classes (numbers, comparison operators, identifiers), only
the identifier mask moves the headline $S$, to \sameGenSid{} ($\rho = \sameGenRhoId{}$,
\sameGenRhoIdLo{}--\sameGenRhoIdHi{}); the number and operator masks move it by at most
\maskMaxShift{}. Code length alone separates the headline pairs at \sameGenLen{}.

Retention does not produce the strict row's $S$. Within the attack class, draws that fire and
draws that do not separate at \survivorAuroc{}, and $S$ on the strict problems with non-firing
attempts in place of the firing ones is \survivorSwapS{} against \survivorSwapSref{}.

The edit arm, whose pairs are near-copies (similarity \editSim{}, Table~\ref{tab:similarity}),
gives $S = \editS{}$ over \editN{} pairs, $\rho = \editRho{}$. In the one-sided arm of \S\ref{sec:results},
where only the honest class was regenerated, the classifier reaches \armOneG{} against
$B' = \armOneBprime{}$ on that arm's \armOneN{} eligible problems, a gain of
\armOneTfidfDelta{}, while code length alone falls to \armOneLenG{}.

Our attack prompt halves our single-shot firing rate: \trigPublicShare{} of our test-passing
draws offer a public test input as the trigger, which cannot diverge from the honest solution,
and those fire \trigPublicFire{} against \trigNovelFire{} for novel triggers; no stored working
backdoor has such a trigger (\trigStoredPublic{}).

\subsection{The two generators' funnel}
Both generators were run through the identical pipeline. Our honest draws pass the public
tests at \sonnetHonestPass{} and \haikuHonestPass{} of 1{,}444 problems; the second
generator's attack draws pass at \haikuAttackPass{} of 1{,}444 and \haikuUsable{} of those
fire, below the 50-pair minimum \texttt{gate\_s\_samegen.py} requires, so it has no strict
row and the two generators are compared on the headline rows only. Those rows differ in
inertness. \haikuFireInRow{} of the \haikuN{} attacks in the
second generator's row fire (\haikuInert{} inert) against \relFireFirst{} of \sameGenN{}
(\headlineInert{}), the other \haikuUsableOutside{} of its firing draws sitting on problems where
its own honest program failed the tests and which the control therefore drops. The
single-shot firing rate depends on our attack prompt, which halves it
(appendix~\ref{app:robust}).

\subsection{The test harness and the pass flag}
\label{app:harness}
The same-generator arm requires executing generated code, so we built a runner that feeds each shipped
input case to a solution under per-case timeouts and address-space limits. It agrees with
the artifact's own \texttt{solution\_passes\_tests} on \harnessAgreement{} of the analysis
pool, and is strictly conservative there, never crediting a solution the artifact rejects
(\harnessFailWePass{} such cases). We use \emph{our own} flag for both classes, because a checker stricter on one class than
the other would manufacture exactly the artifact this paper documents. $B$ does not depend on
that choice: under the artifact's flag $B = \baselineB$ at $n = \baselineBn{}$, under ours
$B = \baselineBownflag{}$ at $n = \baselineBownflagN{}$, inside the first's
interval (\baselineBLo{}--\baselineBHi{}). We do not length-match either class; the model
chooses its own program length. The monitor
scores in Figure~\ref{fig:monitors} are \texttt{runs/x0/monitor-summary.json} from the MIT
release of that harness \cite{jha2026decorrelation}, used under its notice. Two interpreter-era artifacts in the upstream solutions fall on opposite classes: a
\texttt{stdin} without \texttt{.buffer}, fixed, and \texttt{fractions.gcd}, removed in
Python~3.9, not fixable. $B$ is exposed to them; the same-generator arm, whose code we
generated and ran ourselves, is immune.

\subsection{The token test, run and failed}
\label{app:token}
We attempted to confirm a reported token-level mechanism \cite{orel2026aicd} in our setting and
it does not replicate. Separation is \tokenSep{}, the wrong sign, at permutation
$p = \tokenP{}$. The reason is register. Their human class is general-purpose repository
code, whereas both of our classes are competitive-programming code, so an identifier
axis that separates general human code from model code does not separate these two
populations. Only 8 of their 10 canonical tokens are in our vocabulary, so the test is
underpowered; but an underpowered true effect would still carry the right sign, and this one
does not. We report it because a reader who knows that work may run exactly
this test.

\subsection{A third channel, noted but not developed here}
In the same five agentic settings a fifteen-word regular expression over the untrusted
policy's own scratchpad reaches \cotLow{}--\cotHigh{}, because prompted attack policies
restate their side task in the reasoning the monitor is given. We note this only to bound
the claim. The instrument is not ours, and the work it comes from \cite{little2026length}
validates it against an LLM judge and a length-matched null; we defer to that treatment.
